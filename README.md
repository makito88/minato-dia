# みなと川電鉄 ダイヤ工房

運行パターン（種別・区間・時間帯・間隔・両数）を決めると、待避や単線の交換を考えたダイヤが自動で組まれ、
地図とダイヤグラムの上を列車が走る鉄道ダイヤ設定ゲームです。

## 遊び方
開くと、まずトップページが出ます。**世界・澪洲国（日本にあたる架空の島国。名前は仮）・沿線・店舗・従業員**の5つのレイヤーから、路線図とダイヤ、沿線だより、駅ナカ リサーチ、売店（商品・客層・収支）、店員とシフト、街のカルテ（別のタブ）へ進めます。世界と日本はまだ読み物だけで、準備中のものはそう書いてあります。上の帯の「トップ」でいつでも戻れ、「次から、開いたときにこのページを出さない」で出さないようにもできます（`js/top.js`）。

`index.html` をブラウザで開くだけで動きます（インストール不要・1ファイル完結）。

## 主な機能
- 路線図上の列車アニメーション（出庫・入庫、待避、昼夜）
- ダイヤグラムと駅時刻表（時刻をタップするとその列車の現在位置を表示）
- 乗客シミュレーション（駅間のOD、乗換、積み残し、混雑率）
- 利用目的別（通勤・通学／ビジネス／観光・レジャー／私用・買い物）と駅ナカ消費
- 曜日・天気・季節・景気・イベントによる需要変化、本数と速さによる需要変化
- 地図の表示レイヤー：列車／駅の利用（1時間の乗降）／混雑ヒートマップ（区間ごとの乗車率）／イベントアイコン
- 区間ごとの乗車率、OD表、1日の収支

## 設定資料
- **引き継ぎメモ**：[docs/HANDOFF.md](docs/HANDOFF.md)（守ること・ファイルの地図・作ったもの・これからの方針と候補）。新しいチャットで作業を続けるときは、最初にこれを読んでください。
- **みなと川沿線 街のカルテ**：ゲームの上の帯の「街のカルテ」（「駅ナカ リサーチ」の左。下へスクロールしたときの小さい帯では「街」）から、別のタブで「お金の流れ」が開きます。[docs/machi-karte.html](https://makito88.github.io/minato-dia/docs/machi-karte.html)（公開ページ）。沿線10駅のまわりの施設、駅のある市町村の人口・財政、**お金の流れ**（払う側→受け取る側の図、億円/年）をまとめた架空の設定です。上のタブで「駅と施設」「市町村」「お金の流れ」「施設の一覧表」「歴史」「名所・名産・人物」を切り替えます。「駅と施設」の下には、設定どおりの位置と駅名で描いたイラストの「沿線おさんぽマップ」（設定どおりに描いた下絵 `docs/img/route-map.svg` に、AIで水彩の景色を描き足した `docs/img/route-map-painted.jpg`）があります。峠駅のページと「峠の鉄橋」「鉄橋だんご」「霧野 朔」のカード、港駅のページと「港浜赤レンガ倉庫」「港浜の海岸通り」のカード、名産品の「ブローク・ワッフル」「港浜の鯖のへしこ」「にったの雫」「北門カレー」のカード（名産品で絞ると、上に沿線の味の絵）、温泉駅のページと「湯けむり坂」「元湯の木造湯屋」のカードには、AIで描いた湯ノ谷温泉のイメージ画像（`docs/img/`、雑誌のページ風。左ページの文字は飾り）を載せています。「名所・名産・人物」は、歴史の出来事から生まれた架空の歴史建造物・街並み・名産品・人物の30枚のカードで、種類と駅で絞れ、駅のページ・歴史のその年と行き来できます。「歴史」は1885年から今までの架空の歩みで、年を動かす（または「1885年から見る」で再生する）と、その年の路線（開業前の駅・単線と複線・電化前・鉄橋流失の運休）、沿線の人口、1日の乗客、中央→港の最速が変わります。港浜市の姉妹港ヴェステルハーフェン（オランダの港町に似せた架空の町）の年表と並べて読めます。年に合わせて、教科書の挿絵風の図（AIで描いた6枚：築港・開業・電化・焼け跡・ニュータウン・今の港）が出ます。「市町村」には、犯罪と交通事故の件数（住民1,000人あたり・全国の目安と比べる・多い犯罪と事故の起きやすいところ）と、住み心地（架空の住民アンケート：満足・住み続けたい・7項目・住民の声）と、みなと川電鉄の利用（月1回以上乗る住民・通勤通学の手段・駅で乗る人のうち住民の割合）と、「電車をよく使う町ほど、通勤・通学の満足は高い？」の図があります。「お金の流れ」のいちばん上には「ひとりの家計から見るお金の流れ」があり、架空のモデルの人（緑野市の一人暮らし）の1か月の支出が、何に払った→どこに払った（大家さん・川辺のスーパー・みなと川電鉄・電力会社・市役所など）→最後にどこへ（沿線の人の稼ぎ・町の役所・国と県・沿線の外の会社・海外）とたどれます。費目を押すとその道すじと、つながる名所や港の荷主へのリンクが出ます。「売店の店員」を選ぶと、ゲームの売店で働く店員（売店を出していないときは例の店員）の1か月が見られます。お客さんが売店で払ったお金のうち人件費がいくらで、その人に1日いくら届くか（ゲームの直近の運行日から）、1か月の稼ぎ、暮らし方（ひとり暮らし・学生・家族と・年金とあわせて）ごとの使い方と、その先のお金の行き先がつながります。自分の家計の月の数字も入れられます（入れた数字はそのブラウザの中だけに保存され、どこにも送られません）。「お金の流れ」の下には、いちばん太い流れ「沿線の外の荷主」（1,850億円）の内訳を、どこから（国内・海外の6地域）→何に払う（製品・港の仕事）→最後にどこへ（沿線に残るか、外へ出ていくか）の3段でたどる「港の荷主をのぞく」があります。港の会社6社のカードと、円安・定期便の増便・工場の増設・地元からの仕入れの「もしも」で、売上と沿線に残るお金の違いを試せます。文章と表の版は [docs/machi-karte.md](docs/machi-karte.md)。

## イベントを追加する
`index.html` の `EVENT_DATA` に1件足すだけで、需要・地図アイコン・イベント詳細・運転記録に反映されます。

```js
{id:'yatai', name:'新田の屋台村', icon:'屋', place:'N', pos:[760,250],
 start:1080, end:1320, outdoor:true,
 desc:'新田駅前に屋台が並びます。',
 flows:[{to:'N',amt:4,peak:1110,sd:50,p:2},{from:'N',amt:4,peak:1290,sd:40,p:2}],
 ops:[{st:'N',dwell:0.3,from:1260,to:1320}]}
```

- 時刻は0時からの分（19:30 = 1170）
- `flows` の `from`/`to` を省くと「各駅」。`p` は目的（0通勤・通学 1ビジネス 2観光・レジャー 3私用・買い物）
- `outdoor:true` なら雨・雪で規模が縮小、`weekday` は平日の規模（既定0.75）
- `ops` で会場駅の停車時間を延ばせます

ブラウザの開発者ツールから `minatoDia.addEvent({...})` で試すこともできます。

## 環境音を追加する
録音を `assets/sounds/` に置き（MP3・モノラル推奨）、`data/sounds.json` に1件書き足します。鳴らす場所・時間帯・音量・間隔はすべて設定データで決まり、音声エンジンや中核処理のコードを変更する必要はありません。詳しくは `assets/sounds/README.md` を参照してください。

※ 録音と設定データはブラウザから読み込むため、`index.html` をパソコンで直接開いた場合は録音の代わりに合成音が鳴ります（GitHub Pages では録音が鳴ります）。地図やヒートマップと同じ交通データは `minatoDia.snapshot()` で取り出せます。

## 沿線暦と沿線だより（試作）
運行日を数え、沿線の景気や街の出来事で需要がゆっくり変わります。変化は数字ではなく、「沿線だより」（住民の声・地方紙・不動産屋や商店主の話）で伝わります。

- **運行日**：再生して26:00を過ぎると、次の運行日へ進みます。時刻を巻き戻したり、終わり近くへ時刻を飛ばしてまたいだりしただけでは進みません（その日を2時間分以上再生したときだけ）。
- **景気**：「この日の条件」の景気で、自動（沿線暦）と手動固定（好景気・ふつう・不景気）を切り替えます。両方が重なって掛かることはありません。
  - 自動では、回復→好況→減速→不況が、段階ごとに20〜60運行日のばらつきをもって移ります。需要への影響はおおむね±10%以内で、目的（買い物・飲食・観光は大きく、通勤・通院は小さく）と場所・時間帯（中央の夜、川辺の買い物、温泉の宿泊など）で違います。
  - 地域だけの小さな波（港の工場の追加受注、川辺のモール改装、温泉の平日プラン、中央の在宅勤務の試行、大学周辺の客足の鈍り）が、3〜10運行日ほど起きます。一部は予告→実際の変化→振り返りの順で便りが届きます。
  - 景気と小さな波は「乱数の種＋運行日」だけで決まるので、同じ日をダイヤを変えてやり直すと、同じ条件で改正前後を比べられます。
- **沿線だより**：ヘッダーの「沿線だより」から読めます（駅ごとに絞り込めます）。混雑が続く・普通の待ちが長いのに優等列車が空いている・港へ向かう通勤が増える・観光の増減・川辺の乗り換え待ち・増発後の利用と費用、を数日分の結果から判定して届きます。1日0〜2件で、届かない日もあります。答え（「快速を増やして」など）は書きません。
- **4つの見方**：収支の欄に、乗客の便利さ・運賃と特急料金・運行費・沿線のにぎわい（街で使われるお金の目安。電鉄の収入ではない）を分けて表示し、直近7運行日と比べます。
- **新しい街の流れ（試作）**：港の工場への通勤、大学病院への通院、温泉は午後に着き朝に帰る、を切り替えられます。すべて切ると、今までと同じ需要になります。
- **設定**：`data/ensen.json`（景気の段階・感度・上下限、小さな波の一覧、判定のしきい値、便りの文章）。保存はブラウザの `dia-ensen`。
- **開発用**：アドレスの最後に `#dev` を付けると、沿線だよりの下に景気の値・小さな波の予定・駅と目的ごとの補正・判定の候補と実際の数値が出ます。「次の運行日へ」「7日進める」「種を変えて最初から」のボタンもあります。

## 駅ナカ リサーチ（第1段・試作）
ヘッダーの「駅ナカ リサーチ」から開きます。まだ何も売っていない状態から、どの駅のどこに何を置くかを決めるために、まず調べます（売るのは次の段から）。

- **調べる場所**：10駅 × ホーム／改札内コンコース／改札口の前／改札外（駅前）。場所ごとに通る人が違います（ホームは乗る人、改札の前と駅前は電車に乗らない街の人も通る）。
- **調べ方**：「人の流れを数える」（1日3万円）と「聞き取り」（1日6万円）。日数は1・3・7・14日です。
- **運行日を使う**：26:00をまたいで沿線暦が次の運行日へ進むと、終わった日の分が1日分の記録になります。曜日・天気・季節・イベントはその日の条件しだいなので、いろいろな日を調べるほど差が見えて、幅がせまくなります。
- **調査中の映像**：選んだ場所を、その日のシミュレーションの人の流れで描きます。通る人は実際の時間の速さで描くので、「1分間に6人」なら画面を1分見ていると6人通ります（多すぎるときは「絵の1人＝○人」にまとめます）。ホームは島式ホームとして、奥の線路（列車が見える）と手前の線路（画面の外）にダイヤどおりの列車が着きます。乗る人はそのホームの乗る人の割合で少しずつ来て、ドアが開いているあいだに乗ります（奥はドアへ、手前は画面の下へ）。降りる人はドアが開くと出てきます。「いま待っている人」も、前の列車が出てからの時間×乗る人の割合で出すので、絵と数字がそろいます。リサーチ画面を開いているあいだは×1（実際の速さ）で、閉じると元の速さに戻ります。ホームではダイヤどおりに列車が着いてドアが開き、数えた人数が時刻とともに増え、聞き取りで集まった声が吹き出しで出ます。
- **レポート**：時間帯ごとに通る人（目的別）、立ち止まれる時間（ホームは列車の間隔から出す待ち時間）、曜日・天気・イベントの差、客層（目的・年代）、電子マネーと現金の割合、紙の雑誌・漫画雑誌を買う人、酒・たばこ（年齢確認が要る）を買う人、ほしい物、お客さんの声。聞き取りの割合には、答えた人の数から見た幅を付けます。
- **試算**：自販機・売店・駅ナカコンビニ・無人決済コンビニ（電子マネーだけ）・立ち食いラーメン・ミックスジューススタンド・シュークリーム専門スタンド・期間限定ワゴンから選ぶと、1日の売上（少なめ・見込み・多め）、1か月の費用（仕入れ・捨てる分・人件費・場所代・電子マネーの手数料・システム月額など）と損益、はじめにかかるお金と取り戻すまでの月数、赤字になる見込み、注意点（現金の人は買えない、混む時間にさばききれない、本人確認の機械がないと酒・たばこは売れない、話題は時間とともに落ち着く）を出します。同じ場所で業態をくらべる表もあります。
- **売れる前提にしない**：幅には「調査で減らせる部分」と「置いてみないとわからない部分（商品の好み・話題性・まわりの店との相性）」があり、後の方は調べても減りません。実際に置いて確かめるのは次の段（試し置き）です。
- **売店へ**：レポートの上の「○○駅・○○に売店を出す…」で、売店の画面をその駅と場所を選んだ状態で開きます（ホーム・改札内・改札口の前のとき。売店をもう出しているときは「売店を見る」）。
- **目安の出典**：無人決済店の規模と月額、ホームのラーメン店の1日の杯数、自販機1台の売上、NewDays の電子マネー比率、雑誌・漫画の市場の推移、ポップアップ出店の費用、年齢確認のしくみなどは、`data/research.json` の `src` に出典付きで書いてあります。資料が見つからなかった数字には「仮」と書いてあります。
- **設定**：`data/research.json`（場所・街の人の数・年代・支払い・ほしい物と声・調べ方の費用・業態ごとの費用と売れ方）。計算は `js/research-core.js`、画面は `js/research-view.js`。保存はブラウザの `dia-research`。
- **開発用**：アドレスの最後に `#dev` を付けると「きょうを1日分として記録」のボタンが出ます。開発者ツールでは `minatoResearch.recordToday()`、`minatoResearch.reset()`。
- ゲームの1日の収支には入れていません。

## 売店の運営（第2段・試作）
ヘッダーの「売店」から開きます。駅と場所（ホーム・改札内・改札口の前）を選んで売店を出し、限られた棚に何をどれだけ置くか、値段と仕入れ数、店員のシフトと時給を決めて運営します。

- **売店の正面**：左の壁フック（日用品・飴）、上の吊り下げ（菓子・グミ）、冷蔵ケース（飲み物・お酒）、中央の棚（パン・おにぎり・サンド・菓子）、奥のたばこ棚、ホットケース、ホット飲料、傘立て、新聞・雑誌ラック。棚の在庫が減り、売り切れると赤い札が出ます。枠を押すと棚割りの画面に移ります。
- **商品**：17ジャンル72品（名前はすべて架空）。それぞれに値段・原価、温度（冷・温・常温）、手軽さ、健康志向、突発的に要る物（傘・充電器など）、温め・調理が要るか、映え、常連向き、マニア向き、年齢確認（酒・たばこ）、日持ち（その日限り・返品できる新聞と雑誌）、味（甘さ・濃さ・量）があります。
- **お客さん**：その日のダイヤで乗り降りする人から、売店に寄る人が決まります（立ち止まれる時間が長いほど寄る）。客層は会社員（男性・女性）・女子高生・男子学生・年配の人・観光客・買い物の人の7つで、時間帯・天気・季節によってほしい物が違います。
- **買う・買わない**：棚に見えている品から選び（並べた列の数と目の高さで目につきやすさが変わる）、値段が世の中のふつうの値段より高いと値段に敏感な客層から買わなくなります。売り切れ、置いていない、列が長くて電車の時間に間に合わない、でも帰ります。「見たけど買わなかった」人と理由も数えます。
- **商品カード**：棚の絵の品を押すと、その品のカードが出ます（棚と裏の在庫、きょう売れた数・売り切れで逃した数、次の便でいつ何個届くか、仕入れ数を変えるといつから・いくつ変わるか、臨時便、値段）。絵の下には売り切れ・品出し待ち・残りわずかの品が並び、押すと同じカードが出ます。棚の札は売り切れが赤、残りわずかが黄色です。商品の表では仕入れの変更が「きょう8から＋4」と出て、まだ効いていない変更は「発注の予定」にまとまり、取り消せます。
- **仕入れの締め切りと臨時便**：仕入れ数は20:00の締め切りまでに変えると次の運行日の便から、過ぎるとその次から届きます（その日の便は変わりません）。急ぐときは臨時便（1回3,000円＋原価・頼んでから1時間後に届く・1日2回まで・6:00〜20:00）。まだ届いていない臨時便には、到着の20分前まで別の品も同じ料金でのせられます（同じ品なら前の注文に追加、違う品なら「同じ便にのせる」か「別の便で頼む」かを確認してから）。
- **品出し・仕入れ・廃棄**：1日3便（朝・昼前・午後）。飲み物・ホット飲料・栄養ドリンク・ホットスナックは昼前と午後の便でも目標の数まで足します。その日のうちに売る物（おにぎり・サンド・ドーナツ）は売れ残ると廃棄、パンは2日、新聞・雑誌は返品。ホットスナックは冷凍で届き（3便とも裏の目標の数まで）、ケースには「この先45分に売れそうな数」だけ温めて並べます。売れそうな数は、それまでの日の時間帯ごとの売れ方から覚えます（売り切れで買えなかった人も、ほしかった数に入れる）。ケースが空になるとすぐ温め、閉店の30分前からは温めません。温めた物は保温時間（2時間）を過ぎたら捨てます。
- **評価・SNS・常連・マニア・ブーム**：買った人の一部が評価（「甘すぎた」「量が少ない」「この値段ならうれしい」など）を残し、同じ声が続くとお知らせが届きます。映える品はSNSに投稿され、しばらく買いに来る人が増えます。よく買われる品から常連ができ、目当ての品がない日が続くと来なくなります。漫画誌の発売日（月曜）や新しく置いた品にはマニアが来ます。世の中には唐揚げ・生ドーナツ・フルーツサンド・塩パンのブームが順にやってきます。
- **気分（買ったきっかけ）**：買う人ごとに「きっかけ」がつきます。買うつもりで／なんとなく（買う気はなかったのに、目につく・安い・手軽・映える品を手に取る）／行列が気になって（会計に人が並んでいると、なんとなく寄った人が買いやすい）／前の人につられて（数分前に同じ品が売れていると選ばれやすい）／SNSを見て（話題の品を目当てに来る）／ブームで／新商品が気になって（置いてから3日）／雨が降ってきて（傘）／いつもの（常連）／発売日を待って（マニア）。2品目は「ついでに」。さらに、その日ごとにジャンル別の「気分」のぶれがあり（甘い物がよく出る日、パンが出ない日など。新聞・たばこ・日用品・傘はぶれません）、はっきり多かった日はお知らせが届きます。きっかけは売れ行き・吹き出し・商品カードに出て、「客層・時間帯」に「買ったきっかけ」のグラフがあります。数値は `data/kiosk.json` の `mood`。
- **売れ行きの絞り込み**：「売れ行き」の上で、種類（会計・見たけど買わなかった・評価・SNS・品出しなど）、客層、買ったきっかけ（「ついでにもう1品」も）、ジャンル、商品、買わなかった理由、評価（★1〜2・★3・★4〜5）、時間帯で絞れます。絞った分の件数・売上・客単価・買った割合・平均の星・よく売れた品・きっかけ・客層・買わなかった理由がまとめて出ます（ジャンルや商品で絞ったときの「よく売れた」には、いっしょに買われた品も入ります）。「表として保存（CSV）」で、絞った分を表計算ソフトで開けるファイルにできます。対象はきょう（いま開いている運行日）の、いまの時刻までです。スマホでは「絞り込み」を押すと開きます。
- **売り切れで逃した数は見えない**：売り切れの棚の前で買えずに帰った人の数は、売れ行き・商品カード・商品の表・客層のグラフ・お知らせ・CSVのどこにも出しません（「見たけど買わなかった」の数にも入れません）。どれだけ逃したかは、売り切れた時刻や棚の様子から想像してください。お知らせは「売り切れてから、棚の前で残念そうにする人がいたようです」とだけ届きます。見えるように戻すときは `data/kiosk.json` の `hideLost` を false に。
- **店員とシフト**（「店員」タブ）：店員は一人ずつ、名前（架空）・種類（学生・主婦主夫・フリーター・シニア）・得意なこと（レジ・品出し・接客）・入れる時間・週に働きたい時間・時給・やる気・慣れを持ちます。
  - **シフト**：「平日・土曜・日曜祝日」の型ごとに、朝（6〜10時）・昼（10〜14時）・夕方（14〜18時）・夜（18〜23時）に誰が入るかを決めます。変更は次の運行日から。だれもいない時間は売店を閉め、ホットスナックも温めません。会計と品出しは、その時間にいる人だけがします。
  - **おまかせシフト**：「人件費を抑える」（各時間帯1人）と「混む時間は多めに」（1人あたり1時間の会計がおよそ20人までになるよう最大3人。見込みは型ごとのこれまでのお客さんの数）。入れる時間と週の希望を見て組み、あすから効きます。「いまのシフトに戻す」で取り消せます。
  - **時給**：一人ずつ50円きざみで変えられます（次の運行日から）。人件費はシフトの時間×時給で、22時からは2割5分増し。
  - **やる気**：時給が希望より高い・低い、シフトが希望より多すぎる・少なすぎる、1時間に会計する人が多すぎる（1人あたり22人超）、昇給の返事を待たせる、で上下します。やる気は仕事の速さと接客（評価の星、「店員さんの感じがよかった」「無愛想だった」の声）に効きます。下がると「辞めたそう」と知らせが来て、そのままだと辞めます。カードに「気にしていること」が出ます。
  - **慣れ**：働いた日数で仕事が速くなり、30日ごとに昇給の相談に来ます（上げるとやる気が上がり、見送るか待たせると下がる）。
  - **募集と採用**：時給を決めて募集を出します（1回5,000円・3日間）。時給が高いほど応募が多く、応募は運行日の終わりに届きます。採用すると次の運行日から働けます（最大8人）。辞めてもらうこともできます。
  - 前の保存（店員の人数だけ）は、開いたときに同じ人数が各時間帯に入る店員の顔ぶれに置きかえます。数値は `data/kiosk.json` の `crew`、計算は `js/kiosk-staff.js`。
- **万引きの疑い**：寄った人のうちわずかな割合で、棚の小さな品が1つなくなります。気づくのは次の品出しのときで、売れ行きに「○○の数が合わなかった（万引きの疑い）」と出ます（絞り込みの種類にもあります）。なくなりやすいのは、入口に近いフック・吊り下げ・ラックの小さな品と、改札口の前、その町の犯罪の多い駅、店員が1人の時間、レジが混む時間、夜。たばこと温かい物は店員の後ろなのでなくなりません。原価が損になり、「収支」に数と割合（売れた数となくなった数の合計に対する割合）が出ます。防犯ミラー（1日80円）・防犯カメラ（1日550円）・声かけと掲示で減らせます（次の運行日から）。数値は `data/kiosk.json` の `shrink`。
- **かご（1回の買い物）**：最初の1品のあと、客層と時間帯しだいで2品・3品と足します。足す品は、最初の品との相性（パンとコーヒー、おにぎりとお茶、お酒とおつまみ、ホットスナックとビール、新聞とコーヒーなど）で選ぶことが多く、ときどき関係のない品（「ついでに」）や、同じ品を2つ買う人もいます。売れ行きには「〔一緒に○○〕」「〔ついでに○○〕」と出ます。「客層・時間帯」に「客単価と点数」（点数ごとの人数と客単価、客層・時間帯ごと）と「一緒に買われた組み合わせ」（回数と相性＝たまたまの何倍か、定番・似た品・意外）、商品カードに「一緒に」買われやすい品、売れ行きの絞り込みに「点数」があります。数値は `data/kiosk.json` の `basket`。
- **途中で変えられる**：棚割り・値段・仕入れ数は、変えた時刻から先だけが変わります（それより前の売れ方はそのまま）。運行日が終わると締めて、その日の最後の設定が次の日からの設定になります。
- **収支**：売上、仕入れ原価、廃棄、人件費（シフトの時間×時給）、募集の広告、場所代（売上の一定割合か最低額）、電子マネーの手数料、電気代。
- **ジャンルで絞る**：商品の表の上のボタンで、ジャンルごと、または「要注意」（売り切れ・品出し待ち・残りわずか）の品だけに絞れます。スマホでは横にすべらせて選びます。
- **スマホ**：画面が狭いときは、商品の表がカード（値段・仕入れ数の大きな＋−ボタンつき）に切りかわり、棚割りの品の選択は画面の下に出ます。
- **映像**：開いているあいだは×1（実際の速さ）。会計した人・見て帰った人・評価・SNS投稿が吹き出しで出ます（速いときは絵にするのは1秒に3人まで。全部は「売れ行き」に出ます）。
- **設定**：`data/kiosk.json`（商品・ジャンル・客層・棚・便・ブーム・評価の文）。計算は `js/kiosk-core.js`、画面は `js/kiosk-view.js`。保存はブラウザの `dia-kiosk`。開発者ツールでは `minatoKiosk.reset()`。
- 試作の制約：シフトは曜日ごとではなく「平日・土曜・日曜祝日」の3つの型です。商品の味や量の作り直し（オリジナル商品）はまだできません。電鉄の1日の収支には入れていません。

## 保存と引き継ぎ
ヘッダーの「保存・引き継ぎ」から開きます。ゲームはふだんからこの端末のブラウザに自動で保存されています（`dia-` で始まる項目：運転パターン・この日の条件・沿線暦・リサーチ・売店など）。ここでは、それをまとめて扱います。

- **一時保存**：いまの状態を、この端末の中に3つまで取っておけます。「戻す」と、その時点の状態に置きかえてページを読み直します。
- **別の端末へ引き継ぐ**：いまの状態を縮めて「引き継ぎコード」（MD1. で始まる文字）にします。コピー、ファイルに保存、リンク（`…/#load=コード`）のどれかでスマホなどへ送り、向こうの「引き継ぎを読み込む」に貼りつけるかファイルを選びます。リンクなら開くだけで確認が出ます。読み込むと、その端末の状態は置きかわります。サーバーには何も送りません。
- 自動で同期はしません。パソコンとスマホを行き来するときは、そのつど引き継ぎコードを作って送ってください。
- 仕組みは `js/save.js`。

## 留守のあいだ
このゲームにはサーバーがないので、ページを閉じているあいだは何も動きません。そのかわり、開いたとき（スマホで裏から3分以上たって戻ったときも）に、前に見ていた時刻から何運行日たったかを数え（区切りは日本時間の朝4:30）、進めなかった運行日を1日ずつまとめて進めます。沿線暦・売店・リサーチがいっしょに進み、終わると「留守のあいだに○運行日 進みました」とまとめ（日ごとのお客さん・売上・損益）が出ます。

- 最後に見ていた日は、そのときの条件のまま締めます。留守にしていた日の曜日と季節は実際の暦から、天気はその日ごとに決まった乱数で決めます（祝日は分からないので平日・土曜・日曜だけ）。
- 留守のあいだは棚割り・値段・仕入れを変えられないので、最後の設定のまま営業したことにします。
- まとめて進めるのは最大14運行日まで。
- 同じ日のうちに開き直したときは、日は進まず、時刻だけ今に合います（売店はその日の朝からいままでの分が見えます）。
- 仕組みは `js/away.js`。開発者ツールの `minatoAway.test(3)` で、3日留守にしたときの動きを試せます。

## 乗車体験（試作）
列車の情報にある「この列車に乗る（試作）」で、客席から見た車内に切り替わります。速さは×1（等倍）と×5。「通常画面に戻る」で、その時刻のまま元の速さ（×30〜×600）に戻ります。

- **客席**：窓の景色は区間ごとに流れます（街・郊外・田舎・海・森・渓谷）。郊外と街は、夕方〜夜・くもりや雨・大雪・春（桜）で絵が替わります。雨や雪は窓にも降ります。
- **ホームに降りる**：停車してドアが開いたら「〇〇のホームに降りる」。終点では少しして自動でホームに降ります。
- **ホーム**：通過する列車、到着・発車する列車が時刻どおりに見え、止まった列車はドアが開きます。のりば（方面）を切り替え、ドアが開いている列車に「この電車に乗る」で乗れます（川辺では本線と温泉支線を乗り換えられます）。
  - 駅名標・時計・発車標・乗換案内（先に着く電車に「先着」）を表示します。
  - 待っている人は、シミュレーションの待ち人数に合わせて増えたり減ったりします。祭りの日は浴衣の人、雨の日は傘を持った人が混ざります。
- **差し替え**：絵は `assets/images/ride/`、使い方は `data/ride.json` にあります（窓の位置・地平線・景色の区間と差し替え条件・ホームの背景と駅の対応・列車の絵とドアの位置など）。コードを変えずに入れ替えられます。
- 列車の位置・扉・混み具合はダイヤとシミュレーションの結果から計算しているだけで、シミュレーションには影響しません。乗っている自分は乗客数に含まれません。
- 試作の制約：絵は1枚のイラストから切り出して加工したもので、解像度は低めです。ホームの背景は、もとの絵から列車を消して景色を継ぎ足しています。乗客・ホームの人は仮の手描きです。
