# 3D運転席モード 試作（proto/cab3d）

本体（`index.html`・`data/`）とは独立した試作ページです。本体のファイルは読み込みも変更もしていません。

## 起動方法
ES モジュールを使うため、ファイルを直接開く（file://）のではなく、HTTP で配信して開きます。
- GitHub Pages：`<公開URL>/proto/cab3d/`
- 手元：リポジトリのフォルダで `python3 -m http.server` → `http://localhost:8000/proto/cab3d/`

URL パラメータ
- `?s=300` … 視点の位置（m）。画面左上のボタンでも切り替え可
- `?bench=1` … 毎フレーム描画して fps を表示（通常は静止画として必要なときだけ描画）
- `?seed=7` … 街並みの乱数（変えると別の街並み）
- `?look=v1` … 変更前（最初の試作）の見た目。付けないと改善版（v2）

## 現在の段階
第1段階：静止画品質の確認（列車は動きません）

## 見た目の改善（v2）
- 陰影：4段のくっきりしたセル陰影 → 8段をなめらかにつないだ陰影（樹木の多角形の角が目立たなくなる）
- 影：影の解像度を 4096 → 2048 にして輪郭をやわらげる。天空光を青みのある色で強め、日陰が黒く沈まないようにする
- 白飛び：露出 1.0 → 0.95、日差しを少し暖色に
- 霞：遠景の霞を少し濃く、空の地平線の色とそろえる
- 色調補正（最後に1回だけ画面全体に）：彩度をわずかに抑える、暗部を青みのある色へ持ち上げる、明るい所をほんのり暖色に、ごく弱い周辺減光
- 道床：角の丸い砕石を1つずつ描いたテクスチャ（灰色に少し茶色）
- 建物の配置・線路の形・カメラ位置は変更なし

## 軽量化（第2段階の前）
- 影は視点が変わったときだけ描き直す（以前は毎フレーム、建物をもう一度描いていた）
- 植え込み・雑草の粒の面数を 1/4 に（法線を球の向きにして丸く見せる）。三角形の総数 約235万 → 約156万
- 建物・線路まわりを 120〜160m 四方の区画に分け、画面に入らない区画は描かない
- 対数深度をやめる（重なる面は polygonOffset でずらしてある）
- 高精細画面での描画の細かさを 2倍 → 1.5倍まで

## 仮設定
- 区間：中央（0km）→ 桜町（3.2km）の途中を想定した仮想区間。駅名・キロ程は本体 index.html の STATIONS を参照し、区間内の線形・街並みは仮
- 狭軌 1,067mm、線路中心間隔 3.8m、自列車は左側の線路
- 線形：直線 → 緩和曲線 → 右 R700 → 緩和曲線 → 直線 → 左 R900
- 運転士の目の高さ：レール面 +2.45m、線路中心から左へ 0.45m

## 使用ライブラリと素材
- three.js r169（`lib/three.module.min.js`）… MIT License（`lib/three-LICENSE.txt`）
- テクスチャ（草・砂利・アスファルト・金網・畑・雲）は、すべて `main.js` の中でプログラムで描画。外部の画像素材は使っていません

## パフォーマンス（第1段階時点）
- 描画回数（draw call）約30、三角形 約235万（影の描画で同じ量をもう一度描く）
- 測定環境：クラウド上のヘッドレス Chromium・GPU なし（SwiftShader によるソフトウェア描画、2コア）で 1280×720 が 約0.5fps。
  GPU のない環境の値なので、実際の PC の性能の目安にはなりません。実機での測定が必要です
- 課題：住宅・樹木を1つの大きなメッシュにまとめているため、遠くの細部も同じ細かさで描いている。
  第2段階で、遠くの建物の簡略化（LOD）、影を落とす範囲の限定、樹木の面数削減を行う予定
