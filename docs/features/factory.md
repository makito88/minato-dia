## おにぎり工場の一晩（試作）

**いまの工場**（2026-11-07）：ページを開くと、4つのラインとも**本当の時刻（端末の時計）の工場がそのまま動きます**（×1）。速さは「いま（×1）」「×60」「×300」「×900」。早送りやつまみで動かしたあとも「いま」で本当の時刻に戻ります。工場の夜は18:00から翌朝まで（0:00〜11:59は前の夜の続き）。昼（12:00〜夜の始まり）は始まる前の様子、朝（終わり〜11:59）は終わったときの様子が出るので、速さを変えて早送りで見ます。釜の火・湯気・ミキサー・ベルトの表面・油の泡・冷ましているパンの湯気などは、速さにかかわらず本当の秒で動くので、×1でも機械が動いているのがわかります（計算は変えていません）。共通の部品は `js/factory-live.js`。いまの速さでは絵は1秒20回。

**センターの発注とつながる**（2026-11-07）：売店の発注があると、工場の4つのラインの20:00の注文は「ほかの店・取引先の分（いままでの夜の番号どおりの数）＋センターの発注（その運行日の全店の合計）」になります。品は売店の商品ID（`data/factory.json` の `kiosk` の欄）で合わせ、工場で作っていない品はセンター在庫の品として扱います。20:00より前は今までどおり見込みで仕込みます。工場の画面では、いちばん新しいセンターの発注を足して回し、記録に「20:00 注文確定：センターから○個」、夜の番号の横に「センターの発注 F0013 の○個を足しています」と出ます。発注がなければ今までと同じです。工場の収支の見積もりには足しません（今までどおり）。
`factory.html` で開きます（いまはゲームの本体とはつないでいない、独立したページです）。駅の売店に並ぶおにぎりを作る、架空の工場「浜手デイリー 港浜工場」（港の工業地帯。1984年に港の貨物線が廃止され、荷物がトラックへ移ったあとの跡地に建った）の米のラインの一晩を、夕方に決めて、夜は眺め、朝に答え合わせします。

- **工程**：洗米 → 浸漬（タンク16）→ 炊飯・蒸らし（釜5つ）→ ほぐし・冷却（同時に3釜）→ 待ち → 成形・包装のライン → 2:30 の包装の締め切り。ここまでに包装した分を 3:05 に工場から出し、川辺の配送センターで店ごとに分けてほかの品と合わせ、4:00 にセンターを出て 5:00 に中央駅の売店に並びます（時刻表は `docs/ideas.md`）。1釜は200個分。
- **成形・包装のライン（機械2本）**：ライン A・B の2本が、同じ具を並んで作ります（1本60個／分、2本で120個／分。仮）。シート成形（ご飯をふんわりした板にする）→ 巻き成形（板で具を包んで三角に）→ 塩振り（両面）→ 包装機（海苔のフィルム）→ ラベル（消費期限＝出荷日の22:00。その夜の製造に決まった期限）→ 検品（重さ・金属・包みの崩れではじく）→ 急冷（20分で18℃）→ 段積み（40個入りの番重に自動で並べて積む）。手で具を入れる工程はありません。具は7種類（塩むすび・昆布・梅・鮭・ツナマヨ・明太子・鯖へしこ）を1種類ずつ作り、検品を通った数が注文に届いたら次の具へ。ご飯は待っている釜から順に使い、塩むすびと鯖へしこ（にったの雫）には雫の米の釜が要ります。具を替えるときは2本とも掃除で止まります（薄い味→濃い味は4分、濃い→薄いは全部洗って15分）。包装機の詰まり・フィルム切れ・ご飯の重さのずれ・金属の反応は、そのラインだけが止まり、もう1本は動きます。ラインが速くなったので、たいていの夜はラインが米を待ち、詰まりは冷却と釜のほうに出ます。
- **人**：ライン2本を4人で回します（ほかに炊飯の釜番が1人）。絵の中に人の形で出て、何かあると吹き出しが出ます。
  - **ラインの係**（青）：具のタンクを足す（500個ごと）、具の切り替えの掃除、シート成形機のご飯の重さのずれに3分で気づいて、そのラインを2分止めて合わせる。
  - **包装の係**（橙）：海苔フィルム（1,000枚・1本あたり約17分）が残り120枚になると足しに来る。包装機の詰まりを2〜4分で直す。
  - **検品・段積みの係**（灰）：検品を見て、積んだ番重の山を10箱ごとに運び出す。
  - **品質管理**（青緑・記録板）：19:00から2時間ごとに温度の記録（冷却・急冷）、毎時30分に1個抜き取り、具の切り替えのたびに表示（品名・消費期限・原材料）の確認。確認を省くと切り替えが3分ずつ早くなりますが、8%の確率でラベルが前の具のまま。次の抜き取りで見つかり、2本とも5分止めて印字を直し、それまでの分を品質管理と検品の係で貼り直します。中身に卵が入っているのに表示に卵がないとき（ツナマヨ）は、捨てます。
  - **休憩**：4人が1人ずつ45分（22:30／0:00／1:30から）。交代の人を呼べば穴はあかず（時給がかかる）、呼ばなければ休んでいる人の仕事をほかの係が見るので遅れます（詰まりは5〜9分、フィルムは4〜8分で足しに来るので間に合わず切れることがある、重さのずれに気づくのは15分後、品質管理の抜き取りは見送り）。
- **4つの時計**：水の時計（水温で吸水の速さが変わる。冬は春・秋の約2倍かかる。足りないと芯が残り、240分をこえると割れる）、熱の時計（冷却の空気へ近づくように冷える。同時に冷やす釜が多いほど遅い）、菌の時計（炊いたあと10〜52℃にいるあいだだけ増える）、ラインの時計（A・B の様子とフィルムの残り、休憩中の係）。
- **詰まりは前へ逆流する**：冷却がいっぱいだと、炊けた米は釜で待ち（蒸れすぎ）、釜が空かないのでタンクの米が浸かり続けます。
- **見込みと注文**：釜の数は見込み（6,000個）で決め、本当の注文は20:00に具ごとに届きます。米の種類ごとに要る釜を数え直し（はじく分の予備3%）、足りなければ追加の釜が列の最後に並び、多ければ洗う前の釜を取りやめます。見込みで作り終えた具の注文が増えていたら、その具は最後にもう一度作ります。注文の分がそろったら、残ったご飯は飼料へ。
- **夕方に決めること**：季節、仕込む釜の数、洗米を始める時刻、浸す時間、冷却の強さ（電気代が変わる）、ラインの4人の休憩の時間帯と交代の人、具の切り替えのときの表示の確認、具を作る順番（薄い味から／注文の多い順／雫を先に。初期値は「雫を先に」、洗米の開始は18:15）。
- **眺める**：工程の絵（釜・タンク・トレイを押すとその釜を追いかける）、釜ごとの一晩の帯、工場の記録。速さは×1（実際の速さ）〜×900。
- **朝の答え合わせ**：積めた数・具ごとの足りない数・はじいた数・不合格・間に合わなかった数・余り・ラインが止まった回数と分・人の数と仕事の回数（フィルム・具の補充・番重の山・温度の記録・抜き取り）・重さのずれやラベルの間違い・店ごとの番重・いちばん詰まった工程・費用（ラインの機械2本の一晩の費用は仮）。「夜の番号」が同じなら注文も同じなので、条件を1つ変えて回すと、前の夜との差が出ます。
- **設定**：`data/factory.json`（数字はすべてゲームのための仮の目安で、実際の食品衛生の基準ではありません）。計算は `js/factory-core.js`、画面は `js/factory-view.js`。保存はブラウザの `dia-factory`。

### 工場の収支（4つのライン・1晩と1か月）
`factory.html` のいちばん下にあります（どのタブでも出ます）。「見積もる」を押すと、4つのラインを、それぞれのタブに保存してある夕方の条件で10夜回し、平均の収支を出します。
- **売上**：売店の仕入れ値（`data/kiosk.json` の原価）×（1−配送センターの取り分）。取り分は10%・15%・20%から選びます。
- **費用**：ラインの費用はゲームの計算どおり（人件費・材料と包材・機械と電気とガス）。ほかに、ラインの外の費用（社会保険など・工場長と事務と検査の人・建物と設備〈月200万・300万・400万円から選ぶ〉・水道光熱の基本分・工場→センターのトラック・洗浄と衛生用品とごみ）。すべて仮の数字です。
- **おにぎりの新しい取引先**：港の工場の社員食堂900個・大学の売店800個・病院の売店600個・温泉の旅館の朝の売店700個（架空）。選ぶと、米のラインの見込みが増え、釜の数も見込みに合わせ、番重の行き先にも出ます。
- **おにぎりを増やす設備**：洗米機+1・釜+2・冷却+2・浸しタンク+4（1晩15,000円・仮）。洗米機は台数を持てるようにしました（`wash.lines`）。3,000個増やすなら、設備を足して冷却を「強」にすると、春・秋の20夜すべて間に合いました（計算で数えただけ）。
- **見積もりの例**（10夜の平均・計算で数えただけ）：初期値（サンドの食パンは自社で焼く）で1晩約1.8万円、食パンを仕入れにすると約7万円、さらに取引先4つ・設備・冷却「強」で約26万円、さらに取り分10%で約35万円。
- **設定**：`data/factory.json` の `pl`。計算と画面は `js/factory-pl.js`。選んだものはブラウザの `dia-factory-pl`。

### パンのライン（試作）
`factory.html` の上の「🍞 パンのライン」で切り替えます（`factory.html#bread` で直接開けます。米のラインの画面はそのまま）。どちらのタブも、いちばん上にできあがりのイメージ（AIで描いた絵。にったの雫のおにぎり2品／袋入りのパン5品）が出て、品名はあとから文字で重ねています（`docs/img/factory-onigiri.jpg`・`factory-bread.jpg`、位置は `data/factory.json` の `photo`）。売店のパン5品（メロンパン・あんパン・クリームパン・カレーパン・塩バターパン）を作ります。
- **工程**：仕込み（ミキサー1台・15分）→ 一次発酵（発酵室27℃・箱6つ）→ 分割・丸め（1分50個）→ ベンチタイム（15分）→ 成形（人の手。1人1分3〜5個）→ ホイロ（二次発酵・台車4台）→ 焼成（オーブン1台に1回100個。200個の生地は2回に分ける。カレーパンはフライヤーで揚げる）→ 粗熱取り（台8つ。中が30℃まで冷めたら包む）→ 包装（1分40個）→ 2:30 の締め切り。消費期限は出荷日の翌日22:00（その夜の製造に決まった期限。売店のパンは2日もつ）。
- **発酵の時計**：生地は酵母が生きているので、生地の温度で膨らむ速さが変わり（10℃上がると2.5倍、38℃をこえると弱る）、**待ってくれません**。焼く番が来ないあいだもホイロの中で膨らみ続け、進みすぎると酸っぱく形がだれ、もっと進むとしぼんで出荷できません。足りないまま焼くと固く重くなります。絵の生地の箱と台車は、進みに合わせてふくらみます。
- **仕込みの間隔とオーブン**：ミキサーが次の生地をこねる間隔が、オーブンの焼ける速さより短いと、ホイロに生地がたまります（ダイヤの「間隔」と同じ見方）。夕方の画面に「1時間に何回こねる／何回分焼ける」が出ます。
- **夕方に決めること**：季節、仕込みを始める時刻、仕込みの間隔、オーブンの台数、こね上げの温度（仕込み水の温度＝こね上げ×3 −（粉＋部屋＋摩擦）が出る。冬は熱い水、夏は冷たい水）、酵母の量、一次発酵の時間、ホイロの温度と時間、成形の人数。
- **注文**：見込み1,800個で仕込みはじめ、20:00に品ごとの注文が届くと、まだこねていない生地の数を直し、足りなければ列の最後に追加します。
- **朝の答え合わせ**：品ごとの送れた数・足りない数・捨てた数、焼くときの二次の進みの幅、品質、いちばん詰まったところ、費用（人件費・酵母・小麦と具と袋・オーブン・フライヤー。すべて仮）。同じ夜の番号で条件を1つ変えると、前の夜との差が出ます。
- **春・秋の20夜で試した数字**（計算で数えただけ）：初期値で足りない夜1、冬1、夏3（パンが冷めにくく、包むのが遅れる）。オーブン1台にすると20夜すべて足りず、焼く番を待つ生地がしぼむ。仕込みの間隔30分も20夜すべて足りない。
- **まだのこと**：米のラインと人（成形）を取り合う、売店の注文とつなぐ（パンは2日もつので、前の夜の残りも数える）、ドーナツ（揚げ）。
- **設定**：`data/factory.json` の `bread`。計算は `js/bread-core.js`、画面は `js/bread-view.js`。保存はブラウザの `dia-factory-bread`（いま開いているラインは `dia-factory-tab`）。

### サンドイッチのライン（試作・チルド・機械のライン）
`factory.html` の上の「🥪 サンドイッチのライン」で切り替えます（`factory.html#sand` で直接開けます）。売店のサンドイッチ5品を、機械のラインで作ります（実際のサンドイッチ工場の動画と、ユーザーの検討資料を参考にした一般的な形。名前や数字は架空）。
- **品とサンドを分ける**：品は1パック。ラインで作るのは「サンド（1組＝食パン2枚、切ると2切れ）」で、具は たまご・ツナ・ハムレタス・カツ・フルーツの5種類。たまご・ハムレタス・カツ・フルーツは同じ具2切れで1パック、**ミックスはたまご・ツナ・ハムレタス（チーズなし）を1切れずつ**。ミックスのたまごとハムレタスは、単品と同じ流れで作ったサンドを切り分けて使い、ツナだけ別に作ります。ハムレタスはチーズなし、カツはキャベツなし（この工場の規格）。
- **商品規格（原材料・アレルゲン）**：タブの上に表があります。原材料ごとにアレルゲンを持たせ、品のアレルゲンは原材料から集めます（太字＝表示が義務の特定原材料9品目、細字＝準ずるもの20品目。2026年10月時点の区分）。品を替えるときの洗浄の長さもここから決まり、前のサンドにあって次のサンドにないアレルゲンがあれば全部洗います。原材料とその表示はこの工場の架空の設定で、実在の製品の表示ではありません。
- **具材の仕込み**：たまごサラダ（殻つき卵から：スチーマー→冷水→殻むき機→人が確かめる→和える）、レタス（人が選ぶ→洗い槽・殺菌→脱水機）、カツ（冷凍・衣つきを揚げる→急速冷却機で10℃まで）、フルーツとツナサラダ（同じ係）。ハムは切ったものが届きます。**「時間がたったら」ではなく「合格したら」在庫になります**：冷却（カツ）・洗浄と水切り（レタス）・配合（たまご・ツナ・フルーツ）は、品質確認の人の確認を待ちます。
- **品質確認の人（1人）**：初品確認（始業と品の切り替えのあと。ラインは確認が終わるまで動かない）・冷却の合格・洗浄の確認・配合の確認・保留の評価を、この順に片づけます。
- **品の切り替え**：残った具材・ラベル・包材を下げる3分 → 洗浄（短い5分／アレルゲンが残るなら15分）→ 初品確認と表示の照合。初期値の順番（たまご→ツナ→ハムレタス→カツ→フルーツ）では、全部洗うのはカツ→フルーツの1回です。
- **組み立てのベルト**：食パンの供給機・盛り付け機（たまご・ツナ・クリーム）・人がのせる持ち場（ハム・レタス・カツ・果物）。ベルトの速さを決め、人が追いつかなければそこまで遅くなります。供給機と盛り付け機はときどき詰まり、たまごサラダに殻のかけらが残った回は捨てて作り直します。
- **冷たさの時計と保留**：台に出した具材のトレーは作業室の温度へ温まります。10℃こえが3分をこえると減点、20分をこえた分は**保留**にして、品質確認の人が評価します（30分までなら減点つきで出す、こえたら捨てる。仮の線）。
- **そのあと**：締め → カット（機械・1組を2切れ）→ 三角パックに詰める（人。同じ具2切れは1人1分13パック、ミックスは8パック）→ 2:30 → **終業の分解洗浄**45分（3:30までが目安）。
- **消費期限**：出荷日の翌日 6:00。その夜の製造に決まった期限で、包装が遅れても延びません。期限を決めたときに確かめた範囲（包装から33時間まで）より前に包んだ分は出荷しません。
- **夕方に決めること**：季節、具材の仕込みの開始（初期値21:00）、組み立ての開始（22:30）、作業室の温度、トレーの大きさ、ベルトの速さ、のせる人数、パックに詰める人数、レタスを選ぶ人数、レタスの水切り、締めの時間、組み立てる具の順番。
- **春・秋の20夜で試した数字**（計算で数えただけ）：初期値で足りない夜0。のせる人2人で2、トレー100組分で2、締め15分で20、組み立て23:30開始で16（分解洗浄が3:30をこえる夜5）。作業室18℃・トレー400組分・3人だと、20夜で14組が保留になる。品質確認の人の仕事は一晩50分ほどで、ラインが確認を待つことはほとんどない。
- **食パン：仕入れ／自社で焼く（角型）**：夕方の画面のいちばん上で選びます（初期値は自社で焼く）。現実には焼くのはパンの場所でも、作業の流れとしてはこのサンドイッチのラインの一部として、同じ時計で午後から進めます（自社で焼くときは夜の始まりが食パンの仕込みの時刻になります）。
  - **工程**：こねる（1回＝型12本・20分）→ 一次発酵60分 → 分割・丸め → ベンチ20分 → 成形・型詰め → ホイロ（38℃・台車3台。型の8分目まで膨らんだら焼ける。焼く番を待つあいだも膨らみ続け、膨らみすぎるときめが粗く、もっと進むと焼いたあと腰が折れて使えない）→ 焼成（角型3斤・ふたつき。オーブン1台に1回12本・38分＋入れ出し4分）→ 型から出して冷ます（芯が32℃に下がるまで切れない。棚は96本まで。いっぱいだとオーブンから出せない）→ スライス（組み立ての15分前から、切った枚数が300枚より少なくなったら次の1本）→ 食パンの供給機。
  - **使えるパンの枚数**：絵の下の段に、切ってある・冷めて切れる・冷ましている・焼いている／ホイロの枚数を積んだ目盛りと、これから要る枚数（赤い線）が出ます。ベルトは切ってある枚数より速くは組み立てられず、足りないと「食パンが切れるのを待っている」で止まります（台のトレーは温まり続けます）。
  - **夕方に決めること**：食パンの仕込みを始める時刻（初期値15:45）、こねる間隔、角型のオーブンの台数、パンの厚み（8・10・12mm＝1本から42・34・28枚。薄いほど供給機で詰まりやすい）、冷まし方（棚で自然に＝部屋の温度へ／冷却室＝12℃の風で速いが電気代）、見込みに上乗せして焼く割合。パンは注文（20:00）より前に焼くので、足りないと20:00に追加でこねますが、冷めて切れるのは夜中になります。
  - 切ってから90分をこえると乾いて少し減点。原材料は「食パン（自家製・角型）」（小麦・乳）に替わり、具材の代金から仕入れの食パン（1枚12円）を使った枚数ぶん引き、焼く人3人・材料・オーブン・冷却室を足します。
  - **春・秋の20夜で試した数字**（計算で数えただけ）：初期値で足りない夜0（20:00の追加で焼いた夜が4つ、ベルトが食パンを待ったのは20夜で合わせて40分）。夏4（部屋が27℃で冷めるのが遅い）、冬1。仕込み17:00で足りない夜0だがパン待ち545分、18:00で20。こねる間隔40分で6、オーブン1台で7（焼く番を待つ型が腰折れ）。上乗せ0%で4、15%なら0（余りがふえる）。冷却室にすると待ち0。仕入れにすると、前と同じ結果になります。
- **前の手作業の形**は、あとで「手作りパンの店」として別の形で出す案にしています（アイデア帳）。
- **まだのこと**：角型のオーブンをパンのラインと取り合う、業務用ゆで卵・完成サラダを買う選択肢、休憩と持ち場の穴埋め、売店の注文とつなぐ、できあがりの画像。
- **設定**：`data/factory.json` の `sand`（角型の食パンは `sand.loaf`）。計算は `js/sand-core.js`（角型の食パンは `js/sand-loaf.js`）、画面は `js/sand-view.js`。保存はブラウザの `dia-factory-sand`。

### ドーナッツのライン（試作）
`factory.html#donut`、または工場の「🍩 ドーナッツのライン」で開きます。トップページの「工場」からも進めます。
- 売店にあるシュガー・チョコ・生ドーナツの3品。生ドーナツはクリームなしの柔らかい生地で、十分に揚げます。
- 仕込み → 一次発酵 → 成形 → ホイロ → 揚げる → 冷ます → 砂糖やチョコの仕上げ → 包装。注文は20:00に確定し、こねる前の分を調整、足りない分を追加します。2:30までの合格品を注文数まで出荷し、消費期限は出荷日の22:00に固定します。
- 季節・仕込みの開始・専用フライヤーの台数・油の温度・油交換の目安・仕上げの人数を選びます。揚げる番を待つ生地の発酵、使い続けた油、冷却、仕上げの待ちが品質や完成時刻に効きます。
- 再生・時刻の移動、生地ごとの予定、記録、朝の個数と費用。工場の収支は4ラインを集計します。同じ夜の番号なら同じ注文で比べられます。
- 「ドーナッツの作り方」で、3品の生地・配合（粉＝100の割合）・工程ごとの時間を見られます。「どこが機械で、どこが人か」の表で、工程ごとの機械・人数・すること・その夜に使う時間がわかります（包装・出荷の人はまだ決めていません）。配合は仮のもので、`donut.products[].recipe` と `donut.stations` にあります。
- 設定は `data/factory.json` の `donut`、計算は `js/donut-core.js`、画面は `js/donut-view.js`。条件の保存は `dia-factory-donut`。検査は `node tests/donut-core.test.cjs`。
- 専用設備で、ほかのラインとは人や設備を取り合いません。冷却棚は十分ある扱い。人件費の深夜・休憩は概算です。数字はゲームの仮定です。売店の注文・在庫・配送との連動は、ほかの工場ラインと同じく未実装です。
