## 駅ナカ リサーチ（第1段・試作）
ヘッダーの「駅ナカ リサーチ」から開きます。まだ何も売っていない状態から、どの駅のどこに何を置くかを決めるために、まず調べます（売るのは次の段から）。

- **調べる場所**：10駅 × ホーム／改札内コンコース／改札口の前／改札外（駅前）。場所ごとに通る人が違います（ホームは乗る人、改札の前と駅前は電車に乗らない街の人も通る）。
- **調べ方**：「人の流れを数える」（1日3万円）と「聞き取り」（1日6万円）。日数は1・3・7・14日です。
- **運行日を使う**：26:00をまたいで沿線暦が次の運行日へ進むと、終わった日の分が1日分の記録になります。曜日・天気・季節・イベントはその日の条件しだいなので、いろいろな日を調べるほど差が見えて、幅がせまくなります。
- **調査中の映像**：選んだ場所を、その日のシミュレーションの人の流れで描きます。通る人は実際の時間の速さで描くので、「1分間に6人」なら画面を1分見ていると6人通ります（多すぎるときは「絵の1人＝○人」にまとめます）。ホームは島式ホームとして、奥の線路（列車が見える）と手前の線路（画面の外）にダイヤどおりの列車が着きます。乗る人はそのホームの乗る人の割合で少しずつ来て、ドアが開いているあいだに乗ります（奥はドアへ、手前は画面の下へ）。降りる人はドアが開くと出てきます。「いま待っている人」も、前の列車が出てからの時間×乗る人の割合で出すので、絵と数字がそろいます。リサーチ画面を開いているあいだは×1（実際の速さ）で、閉じると元の速さに戻ります。ホームではダイヤどおりに列車が着いてドアが開き、数えた人数が時刻とともに増え、聞き取りで集まった声が吹き出しで出ます。
- **レポート**：時間帯ごとに通る人（目的別）、立ち止まれる時間（ホームは列車の間隔から出す待ち時間）、曜日・天気・イベントの差、客層（目的・年代）、電子マネーと現金の割合、紙の雑誌・漫画雑誌を買う人、酒・たばこ（年齢確認が要る）を買う人、ほしい物、お客さんの声。聞き取りの割合には、答えた人の数から見た幅を付けます。
- **試算**：自販機・売店・駅ナカコンビニ・無人決済コンビニ（電子マネーだけ）・立ち食いラーメン・ミックスジューススタンド・シュークリーム専門スタンド・期間限定ワゴンから選ぶと、1日の売上（少なめ・見込み・多め）、1か月の費用（仕入れ・捨てる分・人件費・場所代・電子マネーの手数料・システム月額など）と損益、はじめにかかるお金と取り戻すまでの月数、赤字になる見込み、注意点（現金の人は買えない、混む時間にさばききれない、本人確認の機械がないと酒・たばこは売れない、話題は時間とともに落ち着く）を出します。同じ場所で業態をくらべる表もあります。
- **売れる前提にしない**：幅には「調査で減らせる部分」と「置いてみないとわからない部分（商品の好み・話題性・まわりの店との相性）」があり、後の方は調べても減りません。実際に置いて確かめるのは次の段（試し置き）です。
- **売店へ**：レポートの上の「○○駅・○○に売店を出す…」で、売店の画面をその駅と場所を選んだ状態で開きます（ホーム・改札内・改札口の前のとき。売店をもう出しているときは「売店を見る」）。
- **目安の出典**：無人決済店の規模と月額、ホームのラーメン店の1日の杯数、自販機1台の売上、NewDays の電子マネー比率、雑誌・漫画の市場の推移、ポップアップ出店の費用、年齢確認のしくみなどは、`data/research.json` の `src` に出典付きで書いてあります。資料が見つからなかった数字には「仮」と書いてあります。
- **設定**：`data/research.json`（場所・街の人の数・年代・支払い・ほしい物と声・調べ方の費用・業態ごとの費用と売れ方）。計算は `js/research-core.js`、画面は `js/research-view.js`。保存はブラウザの `dia-research`。
- **開発用**：アドレスの最後に `#dev` を付けると「きょうを1日分として記録」のボタンが出ます。開発者ツールでは `minatoResearch.recordToday()`、`minatoResearch.reset()`。
- ゲームの1日の収支には入れていません。
