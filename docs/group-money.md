# グループのお金の流れ（2026-11-17・ユーザーと決めた形）

現実の鉄道グループに合わせて、**親会社の鉄道・子会社・本社の積み立て**の3つに整理した。お金の流れは、このページを正とする。数字はすべて仮。

## 会社（data/companies.json）
| 役わり | 会社 | 入るお金 | 出るお金 |
|---|---|---|---|
| 親会社 | みなと川電鉄（鉄道） | 運賃・特急料金、駅ナカの家賃（グループの店＋ほかの店） | 運転と車両の経費 |
| 子会社 | みなとスタンド（売店・店ごと） | お客さんの買い物 | 仕入れ・センターフィー（→センター）、**駅の家賃（→鉄道）**、給料・電気など（→外） |
| 子会社 | 川辺ロジスティクス（センター） | 店からの仕入れ代とセンターフィー | 工場の品の代金（→工場）、運賃（→配送会社）、問屋・人・倉庫（→外） |
| 子会社 | 港浜フーズ（工場） | センターからの品の代金、取引先 | 材料・人件費（→外）、運賃（→配送会社） |
| 子会社 | みなと川運輸（配送会社） | センター・工場・荷主からの運賃 | 燃料・運転手・トラック（→外） |
| 本社 | 経営のタブの積み立て | 鉄道の利益×割合、駅ビルと住宅の家賃、線路使用料、**子会社からの配当** | 保守の予算、投資（駅の改良・駅ビル・住宅など） |

## 決まり
1. **会社ごとに損益を分ける**。会社の間のお金（仕入れ・運賃・駅の家賃）は、払った会社と受け取った会社で同じ額。グループ全体（連結）のもうけ＝外から入った−外へ出た＝会社ごとのもうけの合計。
2. **駅の売店の家賃は社内の振り替え**。店は今までどおり家賃を払う（売上×12%か、広さの下限）。受け取るのは鉄道。鉄道の「駅ナカの家賃」（本体の計算・駅ナカの売上×12%）の一部として数えるので、**鉄道の利益は前と同じ**（二重に数えない）。連結では打ち消し合う。
3. **配当**。子会社のもうけの合計が黒字の日に、その30%（`data/keiei.json` の `dividend.rate`）を本社の積み立てに入れる。赤字の日は0（本社からの穴うめはしない）。グループの記録は次の運行日の始めにできるので、配当は1日おくれて入る。
4. キロ・運賃・乗る人の数・ダイヤ・鉄道の利益・店の収支の計算は変えていない。

## どこで計算しているか
- 請求書と会社ごとの出入り：`js/money-core.js` の `groupLedger`（`o.rail` があれば鉄道を親会社として足す）。きょうの鉄道は `window.minatoRail.today()`（本体の計算）、締めた日は `minatoRail.day(日)`（経営のタブの記録）。
- 記録：`dia-group`（会社ごとの合計と会社の間の合計・14日）。運行日の始めに前の日の分を1回。
- 配当：`js/keiei-core.js` の `dividend` と `closeDay`（記録の `div`）。`js/keiei-view.js` の `dayEnd`。
- 画面：「お金の流れ」（`js/money-view.js`）＝グループ全体のもうけ・会社のカード（鉄道が先頭）・子会社の図。経営のタブ＝「グループ全体（連結）」の表と配当。センターの画面の「グループの収支」にも鉄道の行。トップの1行は子会社のもうけ。
- 橋（`data/links.json`）：`rail-to-money`（鉄道をグループの収支へ・読むだけ）、`group-to-keiei`（配当）、`ctc-fee-to-keiei`（線路使用料）、`keiei-to-rail`（投資の効き目）、`company-invoices`（会社どうしの請求書）。

## 整理したこと
- 「お金の流れ」の画面から、緑ヶ丘店だけの前の数え方（`dia-money` をもとにした表示と注意書き）を外した。グループの記録だけを見せる。`dia-money` は「店を増やしたら」の試算のもとにだけ使う。
- 店の請求書の「家賃・電気・手数料など」を、「駅の場所の家賃（鉄道へ）」と「電気・手数料など」に分けた。

## まだ
- 鉄道の人件費・保守・借金の返済は、鉄道のもうけに入れていない（本社の「投資に回す割合」の残りで払ったとみなしている）。そのため鉄道のもうけが子会社よりずっと大きく見える。
- 駅ビル・モールにグループの店を入れる（店の売上と家賃が戻る）。駅前の住宅と配送のつながり。
- 1店だけのときは、センターと配送会社の決まった費用を1店で持つので、子会社は赤字になりやすい（配当0）。店や取引先がふえると黒字になる（「店を増やしたら」の試算）。
