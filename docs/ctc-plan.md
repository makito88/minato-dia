# 長い指令パネルと「自動の指令員」の案（2026-11-16 ユーザーと決めたこと）

## ねらい
- プレイヤーは運行管理のプロではない。**プロのやり方を決まりとしてゲームに入れ、自動の指令員が動かす**。
- プレイヤーは、通過待ち・接続・待ち合わせ・朝のラッシュ・事故の対応が「何が起きて、なぜそうしたか」を**見て分かる**。手を出すのは「方針」だけ。
- 1倍速でも、数分ごとに見どころがある。

## 地図の考え方（line-plan.md を置きかえる）
本当の位置は「キロ」と「時刻」だけ。絵はそれぞれ、キロを自分の絵の上の位置に置きかえる。

| 絵 | 線路の形 | 役目 | いまの状態 |
|---|---|---|---|
| ① 長い指令パネル | まっすぐ・**キロどおりの縮尺**・駅ごとに番線とポイント | 列車の位置・待避・接続・乱れを正確に見る | **これを先に作る** |
| ② 駅ごとの詳しい地図 | 地形を縫って曲がる（ChatGPT の絵） | 駅のまわりの本物らしさ | パネルの番線の形に合わせて、あとで描く |
| ③ 全体のイメージ地図 | 雰囲気 | 沿線全体の場所・夜景・天気 | まだ決めない（今までの絵はどれも仮・見本） |

- ①の縮尺：1km＝200px（本線 21.5km ≒ 4,300px・横にスクロール）。支線 12.9km は川辺から分かれて上の段にキロどおり。
- 番線・ポイント・車庫は `docs/map-tiles/haisen.json`（配線図の案）が元。川辺は `proto/kawabe` と同じ形（proto/ はさわらない。決まりを読んで本体に写す）。

## 自動の指令員の決まり
**判断の順番**：安全 → 運転を続ける・再開 → 列車の間かくをそろえる → 接続 → 定時。
数字（待つ上限など）はすべて仮（`src: assume`）。一般的な考え方で、特定の会社の決まりではない。

| 手筋 | 中身 |
|---|---|
| 通過待ち（待避） | 速い列車が遅い列車を追いこす。どの駅かはダイヤで決まっている |
| 行き違い | 単線の支線で、決まった駅ですれちがう |
| 接続・待ち合わせ | 決まった乗りかえは、相手が遅れても**上限の分数まで**待つ（例：5分） |
| 回復運転・停車時間の短縮 | ダイヤの余裕で遅れを取り戻す |
| 順番の入れかえ・待避駅の変更 | 遅れた普通を先に行かせる／別の駅で追いこす |
| 行き違い駅の変更 | 単線で、相手を待つ駅を変える |
| 間かくの調整 | ラッシュで団子になったら、1本を駅で少し待たせる |
| 接続の打ち切り | 上限をこえたら待たずに出して、次の列車を案内する |
| 予備の編成・途中折り返し・間引き | 大きく乱れたとき（渡り線のある駅で折り返す） |
| 運転見合わせ・振替輸送・運転再開 | 大きな事故のとき |

## 遅れの理由（ディスプレイにも出す）
列車ごとに、いまの遅れと、その理由（いくつでも）を持つ。理由は原因の列車・路線・駅とつながっている。

| 理由 | `code` | 表示の例 |
|---|---|---|
| 混雑（乗り降りに時間がかかった） | `crowd` | 中央で乗り降りに時間がかかったため（+1分） |
| 通過待ち（待避） | `taihi` | 大学前で特急1023の通過待ち（+2分） |
| 行き違い待ち（単線） | `kokan` | 森下で上り8102との行き違い待ち（+1分） |
| 自社の接続待ち | `conn` | 川辺で温泉からの観光特急の接続待ち（+3分） |
| **臨時列車の接続待ち** | `connExtra` | 川辺で臨時列車「湯けむり号」からの乗りかえ待ち（+2分） |
| **臨時列車の通過待ち** | `passExtra` | 緑ヶ丘で臨時列車「客船リレー号」の通過待ち（+2分） |
| **遅れている他社線との接続待ち** | `connOther` | 中央で、5分遅れている県央本線 特急からの接続待ち（+3分） |
| バス・フェリーとの接続待ち | `connBus`・`connFerry` | 港で、ひのき島フェリー最終便への乗りかえを待つため（+2分） |
| 前の列車の遅れがうつった | `follow` | 前を走る普通1012の遅れのため（+2分） |
| 進路の待ち（ポイント・平面交差） | `route` | 川辺で支線から来る列車が平面交差を通るのを待つ（+1分） |
| 乗務員の交代（直通列車） | `crew` | 中央で県央本線からの乗務員の交代（+1分） |
| 貨物列車の待ち | `freight` | 港の手前で貨物列車が引き込み線に入るのを待つ（+1分） |
| 事故・故障・急病の人・動物・天気 | `incident` | 桜町付近で線路に動物（+6分） |
| 回復運転（遅れがへった） | `recover` | 余裕時分で回復（−1分） |

**見せ方**
- **パネルの列車の札**：「+3分 接続待ち（県央本線）」。理由の種類ごとに色と小さな印。
- **駅の発車標**：本物のように「遅れ 3分　県央本線遅れのため」。
- **判断のカード**：起きたこと → 判断（手筋の名前）→ 理由（決まりと数字）→ 結果。しなかった場合の数字（もしも）も並べる。
- **遅れのつながり**：県央本線の遅れ → 中央で接続待ち → 後ろの列車へうつる、を線でたどれる。
- **無線の文字**：「指令から2345列車、大学前で特急を先に通します」。
- **その日の遅れの内訳**：理由ごとの合計の分数（グラフ）。
- 判断の場面では自動で1倍速に。用語は押すと短い説明。

## 臨時列車と貨物列車（他社線からの直通）
**共通**：中央駅の西に、県央本線（5・6番線）とみなと川電鉄をつなぐ**連絡線**を足す。中央で乗務員を交代。電気は両方とも直流1500V（仮）。他社の列車が走ると**線路使用料**が入る（橋・数字は仮）。

**臨時列車（イベント列車）**
- 道すじ：県央本線（中央より西）→ 中央 → 港で折り返し、または 川辺から支線 → 温泉で折り返し。
- 走る日：客船の寄港日・川辺の夏祭り・紅葉の季節の温泉・初詣など（イベントの暦と季節のできごとから）。
- 折り返しのあいだは、港留置線・温泉の臨時列車用の留置線で休む。支線は行き違いの駅の長さで両数を決める（例：6両まで）。
- 乗客は、はじめは今の乗客の計算とは別に数える（今の結果を変えない）。

**貨物列車**
- 道すじ：県央本線（中央より西）→ 中央 → 本線 → 港の手前で**南へ分かれる引き込み線（臨港線）** → 埋め立て地の**港貨物ターミナル**（着発線2〜3本・荷役ホーム・入換の機関車）。港留置線は北側なので、貨物は南側。
- **走る時間：夜と昼のすいている時間だけ**。昼は10〜15時のすき間、夜は終電のあと（0時半〜2時ごろ・保守作業の前）。1日2〜4往復（仮）。
  - 今のゲームの1日は 4:30〜26:00。夜の貨物を見せるため、パネルは26時のあとも動かす。
- 遅く（最高80km/h）長い（12両・約250m）ので、待避線の長さが足りる駅（大学前・緑ヶ丘・川辺）で旅客列車に道をゆずる。
- 港の工場・問屋の荷物を県の外へ。自社のトラック（配送会社）とは「どちらで運ぶか」の関係（トラックの運転手不足で鉄道へ移る流れ＝VISION の「少し先の未来」）。

## 2026-11-17 線路の形をユーザーの絵に合わせた
- 中央：県央本線（他社線）は駅の**北側**（5・6番線）を通って北東へ。西のはしで連絡線（2本）が1・2番線へ。中央車庫は**駅の南西**で、3・4番線の西のはしから入出庫線2本。駅名は線路の下。
- 川辺：温泉支線は駅の**東**で分かれる。下りの本線から上がり、少し平らな所で上りからの線（下りの本線を平面交差）とまとまって、上の段へのぼる（`JUNC0 0.4・LV0 0.5・LV1 0.9・JUNC1 1.3・UP0 0.5・UP1 0.75`）。待避の線は左右対称。
- 温泉：駅のすぐ手前で2線に分かれる。温泉留置線は駅の手前で分かれて**西（左）へ**。
- 頭端の駅（中央・港・温泉）で止まっている列車の札は、横に出して重ならないように。回送は車庫の入出庫線の上を通る。

## 段4 できたこと（2026-11-17）
- **方針**（`CtcCore.POLICY`・数字は仮）：パネルの上のボタンで選ぶ（保存 `dia-ctc-policy`）。プレイヤーが決めるのは方針だけで、指令員の決まりの数字が変わる。
  | 方針 | 接続を待つ上限 | 入れかえを決める遅れ | 回復運転 | 要望 |
  |---|---|---|---|---|
  | バランス（はじめ） | 5分 | 2分 | 3% | 一部を受ける |
  | 定時重視 | 2分 | 1.5分 | 5% | ことわる |
  | 接続重視 | 8分 | 3分 | 3% | 一部を受ける |
  | 売上重視 | 5分（特急・観光特急は1.5分しか待たせない／特急からの乗りかえは8分待つ） | 2分 | 3% | ぜんぶ受ける |
