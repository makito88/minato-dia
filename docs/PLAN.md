## 柱1　売店〜センター〜工場の一周を本物にする（いま進める柱）
ユーザーがいちばん大事にしている流れ（2026-11-09）：**注文した数（おにぎり・パン・サンド・ドーナッツ）→ 工場がその数を作る → センターに届く → センターで他の品と合わせる → 店へ配送 → 店に届く**。数はおまかせのまま。1回に橋1本。

できたこと（2026-11-09。テスト `tests/chain.test.cjs` でおまかせ14運行日をつなぐ）：
1. **注文の時刻**：運行日の注文は、前の日の 19:00 までに確定した数（19:00 の記録）と2日前までの記録だけで決める。
2. **パンは届ける数を作る**：在庫の目標から、次の朝に残る見込みを引いた数だけ工場に頼む（作ったのにセンターに残るパン：14日で30個前後 → 0個）。
3. **かご車**：工場の品を便ごとに何個届けるかはセンターが決める（合計は出荷数とちょうど同じ）。店はそのまま受け取る。
4. **トラック**：センターを出る時刻＋店までの分＋遅れ（仮・雨と大雪で増える）＝店に着く時刻。便の時刻より遅く着いたら、着いた時刻に棚へ。

つぎ（流れの残り）：
5. **工場の遅れ（決め方 D・2026-11-09 にできた）**：締め切り 2:30 に間に合わなかった品が要るとき、最後の品ができるまで15分以内ならトラックが待つ（朝の便がその分遅れる）、長ければ時刻どおり出して追いかけ便で次の便へ（費用 9,000円・仮）。
6. **センターの在庫に限り（2026-11-09 にできた）**：倉庫に在庫を持ち、問屋へ週2回おまかせで発注（次の運行日に着く）。足りなければ店に届く数が減る。倉庫の画面で在庫・発注・入荷・足りなくなるおそれが見られる。
6b. **配送会社の島（2026-11-09 にできた）**：みなと川運輸（グループの運送会社）が工場→センターとセンター→店を走らせ、追いかけ便と積みきれない便は他社（港浜急送）。トラックの1日の画面。トップに4つの会社の窓。
7. **お金の流れ（2026-11-09 にできた）**：会社どうしの請求書（品物の数×値段・運賃）と、会社ごとの1日の入・出・もうけ。画面は「グループのもうけの1行・会社のカード・お金の流れの図」だけ。残り：工場の収支を実際の夜の費用から、ほかの取引先の分、店が増えたときの分け方。
8. **工場の昼の便（当日の橋）**：8:00 出荷 → 10:00 到着 → 12:00 販売（`{day, t, value}` の t を使う最初の橋）。

## 柱2　画面を分かりやすく・軽く
機能は消さない。「いつも見るもの」と「ときどき見るもの」を分ける。1ページずつコミットし、前後で負荷を測る。

1. **メインの画面を3つのタブに**：「走らせる」（地図・ダイヤグラム・時計）／「ダイヤを組む」（この日の条件・運行パターン・1日の成績）／「成績を見る」（利用目的・乗車率・OD表・駅の様子・運転記録）。見えていないタブは描かない。
2. **上の帯**：速さと時刻のジャンプを「×1 いま」と「速さ・時刻 ▼」に、音の調整を「♪ ▼」にまとめる。
3. **売店のタブを8つ → 4つ**：「いま」（売れ行き・荷物の行方）／「品物」（商品・棚割り）／「人」（客層・店員）／「お金とお知らせ」。
4. **トップ**：「きょうの沿線」の下に大きな入口を3つ（走らせる・売店・工場）。そのほかは研究室。
