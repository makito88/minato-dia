# 店内画のアニメ制作記録

この会話の依頼範囲は、密度の高い手描き風の店内で、多様な人物の行動を既存の店の計算とつなぐこと。作業先は `chatgpt`。main・本番公開は別。これは既存の `docs/minato-store-rounds.md` の0〜9回が完了した後に追加された、見た目を育てる作業である。

## 現在動くもの

- 飲料棚へ行く一人。4方向の歩行、手を伸ばす途中の品切れで中断・選び直し。両方なければ買わずに退出。
- 商品を持つ腕と飲料は同じ画像。コーヒーとスポーツドリンクの2種類。
- 順番待ち→レジへ進む→空いている左手でカードをかざす→会計済みにする→横によける→飲料を持って退出。
- 「店員をほかの対応中にする」で待機を続け、「対応を終える」で再開。一時停止・ゆっくり再生・レジまで早送り。
- `stock`（棚）、`unpaid`（持っている未会計品）、`purchased`（会計済み品）を別に保持。取得時に棚から1回移し、会計時は未会計から会計済みへ1回だけ移す。元の売店のデータは変更しない。

## まだ接続していないもの

- 実際の売店から写すのは、入口ボタンを押した時点の飲料2品の在庫だけ。例の客の会計時間・待ち時間は `data/kiosk-scene.json` の仮の値。**実際の行列や会計イベントの再生ではない。** UIにも明記。
- 実際の人の動きや出来事は `js/kiosk-walk.js`、`js/minato-store-anim.js`、`js/minato-store-view.js`、`data/minato-store.json` に既にある。そのルールを描画試作に作り直して重複させない。
- 全員の自律行動、客層別の姿、複数商品・かご、着席、店員と納入業者、ゴミだけの客、全商品が減る棚はまだ。背景のほかの人物は静止画。
- カードでの支払いのみ。店員がスキャンする動き、現金、袋詰め、斜め方向の姿勢、連続的な回転も未実装。購入品を持って歩く試作を消さずに育てる。

## 次に着手する工程

1. `KioskCore.simulate` の既存の出来事を、新しい画面が読む小さな入口を作る。まず対応する一人の購入について、元の品・レジ・順番・時刻を維持する読み取り専用の再生を検証する。描画のために売上や消費を追加しない。今の「例で反応を試す」モードと区別する。
2. 既存の `buy` は `e.t`＝会計開始、`e.end`＝終了、`e.t-e.wait`＝列への到着、そこから `e.stay` を引いた値＝入店（`MinatoStoreAnim.build` 参照）。入店順で並べ直してはならない。セルフへの振り分け・店員ヘルプ・離脱は元の結果に従う。
3. その後、品の配列と保持方法（片手／両手／かご）を扱える状態に広げ、体・動作・持ち物を再利用できる形で二人目へ。専用画像を全組合せ分増やす方式に固定しない。

## 確認済み（2026-11-12）

- `node tests/kiosk-scene.test.cjs`：品切れ中断、選び直し、棚・未会計・会計済みの移動、二重会計防止、対応中の待機と解除、レジ横への移動、退出、再生し直し、15/30/60fpsの一致。
- `node tools/lint.cjs`。
- ブラウザでコーヒー／青い飲料の支払い姿勢、会計済みの表示、飲料を持った退出、390px幅のiframeでレイアウトと操作。横はみ出しなし。スマホ実機は未確認。
- 単体HTMLの書き出しと読み込み。画像・JS・設定を埋め込み約1.86MB。外部通信なしでアニメを再生できる。
- 元の売店の計算と画面処理には変更なし。負荷メーターでの前後比較は未測定。描画は約30fpsで、非表示・停止・終了時は更新しない。
