# 店内画のアニメ制作記録

依頼範囲は、密度の高い手描き風の店内で、多様な人物の行動を既存の店の計算とつなぐこと。作業先は `chatgpt`。main・本番公開は別。既存の `docs/minato-store-rounds.md` の0〜9回が完了した後に追加された見た目の制作。

## 現在動くもの

- 飲料棚へ行く一人。4方向の歩行、手を伸ばす途中の品切れで中断・選び直し。両方なければ買わずに退出。
- コーヒーとスポーツドリンクを持つ腕・指・飲料は同じ画像。順番待ち→有人レジ→カード支払い→横へよける→退出。背景の密度・素材は維持。
- 「反応を試す」：従来の `KioskScene`。在庫と店員対応中の切り替え、一時停止、ゆっくり、早送り。棚 `stock` → 未会計 `unpaid` → 会計済み `purchased` はこの例の中だけの状態。
- **「記録を見る」（2026-11-12追加）**：`KioskSceneRecord.build(res, cutoff)` が `KioskCore.simulate` の実際の結果から、すでに会計を終えた対応対象の最新1件を抜き出す。元の品・レジ到着・会計開始／終了・待ち時間をそのまま使う。会計終了の瞬間に未会計→会計済み。時刻を戻しても売上や在庫に書き戻さない。
- 港駅の店の「店内画で買い物の記録を見る」から `v:2,mode:record` の小さな記録をURLのhashで渡す。`v:1` の従来の在庫だけのリンクも受け取れる。ゲームの保存キー・形は変えていない。
- 記録は3倍速／約1倍速、スライダー、列への到着・会計の開始／終了へ移動できる。通常の見本にも、既存の売店計算から作った実際の1件を同梱（`data/kiosk-scene-recording.json`）。`node tools/kiosk-scene-example.cjs` で再生成できる。例の営業条件であり、ユーザーの保存データではない。

- **「かごで買い物を見る」（2026-11-12・20時の工程）**：既存の売店計算から得たコーヒー2本の記録を再生。空のかごで入店→1本ずつ中身が増える→有人レジで左手のカード支払い→横へよける。2種類合計4本までの組合せを同じモデルで扱う。
- **棚からかごへ移す手（2026-11-13）**：左手を伸ばす→1本を握る→右手のかごへ下ろす→手を離す4姿勢を追加。取った1本は、手を離すまでかごの中に重ねて描かない。「商品を取るところへ」で場面をすぐ見られる。

## 記録の対応範囲と扱い

- まず `salM`、有人 `f`、キャッシュレス、コーヒー／スポーツドリンク合計1〜4本、追加の `carry`・ごみ・店員案内・会計後の飲食がない購入。未対応の客・商品・セルフ・現金等を別の姿やレジへ置き換えない。対応する終了済みの記録がなければ、その旨を表示する。
- `e.t`＝会計開始、`e.end`＝終了、`e.t-e.wait`＝列への到着、そこから `e.stay` を引いた値＝入店。`MinatoAnim.build` と同じ意味。待ち順の前後は `MinatoAnim.qSlot` と同じくレジ到着時刻で判定し、先行客が会計に進んでから0.04分で詰める。先行客の外見が未対応でも、待つ人数には含める。いまは先行客の姿は未描画。
- レジの振り分け・離脱・店員の対応を描画側で再決定しない。`kiosk-walk.js`・`kiosk-core.js`・既存の `minato-store-anim.js` は無変更。
- **記録モードの棚在庫同期は未接続**。`res.snap` は間隔をあけた在庫記録で、手に取る瞬間の数ではない。その数からさらに1本引いたり、仮の残数を「実際の棚在庫」として表示したりしない。記録モードでは在庫上書きの描画をやめ、「棚在庫の同期は準備中」と明記。手元の未会計／会計済みは表示。
- 歩く道・商品を取る瞬間・カードや鞄の姿・会計後の移動は描画用の仮の表現。キャッシュレス記録はカードかスマホかを特定しないので、カードの絵は仮。店を出る時刻も仮であり、営業の記録に追加しない。
