# 取引の相談窓口（2026-11-12 にユーザーと決めた計画）

ほかの会社（問屋・他社のコンビニ・社員食堂・病院の売店・会社など）から「品を売ってほしい」「荷物を運んでほしい」という相談を受け、引き受けると工場・配送会社・お金に反映される窓口。**センターの画面に新しいタブ**として置く。相談・契約・日ごとの結果は新しい保存 `dia-deals`（`{v:1,...}`。引き継ぎコードに入るので小さく保つ）。

## いまの仕組み（関係するところ）
- 工場（港浜フーズ）：運行日の始めに、センターの発注（自社2店の合計・`dia-orders`）で夜の分を作る（`js/factory-night.js`）。それとは別に、ラインの中で「ほかの店・取引先の分」を決まった乱数で作る（おにぎり約6,000個/晩）。足りない夜はこの分から減らす。工場の収支の画面に「おにぎりの新しい取引先」4つ（チェックで作る数が増える・社員食堂・大学の売店など）。
- センター（川辺ロジスティクス）：店の注文をまとめて工場に発注、倉庫の在庫を店ごとの便に割り振る（`js/center-core.js`）。問屋（みなと卸）からは仕入れるだけ。
- 配送会社（みなと川運輸）：工場→センターの定温トラック、センター→店の2トントラック（かご車10台まで）。積みきれない分は港浜急送。`HaisoCore.dayPlan` は `stores` に外の届け先（`ext:true`）を足せる（今は試算だけ）。
- お金：会社どうしの請求書。グループの収支 `MoneyCore.groupLedger`（2026-11-12）。「外の配達先 0/10/20/40」は試算だけ。
- 2店（緑ヶ丘・港駅）の注文は、運行日の始めに `kiosk-view.js` の `dailyOrder` でそろえてから納品書を1回だけ作る（橋 `minato-to-group`）。

## 相談は2種類
| | 販売の相談 | 配送の相談 |
|---|---|---|
| 売る・引き受けるのは | 工場（港浜フーズ） | 配送会社（みなと川運輸） |
| 相手 | 問屋、他社のコンビニ・社員食堂・病院の売店など | 他社の店・会社・問屋（荷主） |
| 条件 | 品（おにぎりの具・パン・サンドなど）、1日の数（平日・土日）、卸値、受け渡しの場所と時刻、期間 | 荷物の種類（常温・チルド・冷凍）、かご車の数、積む場所、届け先、時刻の幅、運賃、曜日、期間 |

販売の「受け渡し」：1 相手が工場へ取りに来る／2 問屋の便で運ぶ／3 店まで届ける。3 のときだけ配送を決める（自社で運ぶなら配送の契約がもう1つ。2つは組で表示するが契約は別々。港浜急送なら費用）。

相談のきっかけ：問屋からの紹介（大口・値段は低め）／相手からの依頼（小口〜大口）／自分から動く（「問屋に相談する」「店に声をかける」で営業の費用。1〜3日あとに何件かの相談）。相談は運行日と保存の種から決まった乱数で作る（同じなら同じ）。届いた時刻と返事の期限（例：3日）。

## 画面
1. 相談の一覧（受信箱）：札（販売・配送／大口・小口／きっかけ）・相手・品または荷物・数・値段・届け先と時刻・期限。絞り込み。
2. 相談の中身と見込み：工場（ラインの空き・締め切りに間に合うか・1日の売上・原価・もうけ）／配送（どの便・かご車の空き・増える時間・距離・運転手の時間・港浜急送の応援がいるか）／自社2店への影響（店に着く時刻の遅れ・工場が足りない夜に自社の店の分が減らないか）。選ぶ：「引き受ける（お試し7日／続ける）」「断る」「保留（期限まで）」。
3. 契約中の取引：日ごとに届けた数・足りなかった数・遅れ・収入。相手の信用（評判）。解約。

## 契約が決まると（時刻つきの、確定した数だけを受け渡す）
| 時刻 | 販売の契約 | 配送の契約 |
|---|---|---|
| 前の日 18:00（仮・画面の確定時刻） | 相手の注文の数が確定（契約の数のまわりで少しゆれる） | 荷主の荷物の量（かご車）が確定 |
| 前の日 20:00 | 工場が、センターの発注とは別の行（「取引先・契約」）として注文に足す。人・材料・機械の時間は今の計算で増える | ― |
| 夜〜朝 | 足りない夜の順番：自社の売店 → 契約の取引先 → 今までの「ほかの店・取引先」。契約の分が足りないと信用が下がる | 配送会社の1日の計算に外の届け先を足す（`ext` のしくみ）。かご車が足りなければ港浜急送の応援便 |
| 届けた時刻 | 納品書に取引先の行と届けた数 | 届け先は自社の店のあと。先にしたい相談は「店が○分遅れる」と出す |
| お金 | 請求書「取引先 → 工場（品の代金）」 | 請求書「荷主 → 配送会社（運賃）」。センターで積みかえ・仕分けをするなら「荷主 → センター（仕分け料）」 |

**計算する時刻（Claude の確認・2026-11-12）**：実際のゲームでは2店の注文も工場の納品書も運行日の始め（朝4:30すぎ）にまとめて計算している。契約の数もそこで「2店の注文 → 契約の注文 → 納品書を1回」の順に足す（画面の確定時刻は 18:00 のまま。数は保存の種と運行日だけで決め、同じ日の中で読み合わない）。

橋（`data/links.json`）を3本：窓口 → 工場（契約の注文の数）／窓口 → 配送会社（荷物の量と届け先）／窓口 → お金（請求書）。最初は「仮の数値」。自社の店のための売り先は探さない。

## 重なりの整理
- 工場の収支の「おにぎりの新しい取引先」4つ：窓口に移す。最初の相談として出し、前にチェックしていたものは契約として引き継ぐ（**移す日の作る数とお金が前と変わらないことをテストで確かめてから**）。工場の収支の画面には結果だけ。
- 工場の「ほかの店・取引先（乱数）」：今までからの取引として残す。新しい契約はその上に足す。
- お金の流れの「外の配達先」の試算：試算として残す。実際の契約は別の行。
