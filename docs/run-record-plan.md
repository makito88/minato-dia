# 運行の記録（共通の計算）と2つのモードの計画

（2026-11-25 の会話で決めた案。手順1〜4はできた〈2026-11-25〉。次は手順5〈代行バス・実際の乗客・運賃と払い戻し〉）

## ねらい
地図・指令パネル・乗車体験・収支・売店が、同じ「本当」を読む。遅れ・事故・代行バス・運賃・売上が、どの画面でも同じ数字に落ち着く。

## 本当にするもの＝「運行の記録」（絵ではなく、線路のキロ程と時刻）
- 時刻：「いまの沿線」は日本時間の今（liveTf）、「試運転」はゲームの T。運行日は朝4:30で切りかわる（今のまま）。
- 各列車の実際の発着：ダイヤ＋その日の乱れ（混雑・小さなできごと・事故・接続待ち・入れかえ・回復運転）。運休も。もとは js/ctc-core.js の disrupt（指令パネルの計算）。
- 走っている途中の位置：「どの駅とどの駅の間の何 km 地点か」。止まる駅の前後はゆっくり（ctc-core の trainPos と同じ）。
- 番線、地図の外の列車（県央本線の臨時・貨物）も同じ表に。

## 見せ方（形がちがっても位置はそろう）
- 地図：2駅の間の km の割合を、絵の曲がった線路の同じ割合の場所に置く。待避線の列車は地図でも待避線の側に。県央本線の列車は中央の西のふちから出入り（地図の外のあいだは札）。運休の列車は走らない。車庫への出入りの絵は今のまま（時刻だけ記録に合わせる）。
- 指令パネル：今の一直線の図のまま。計算を自分でせず、記録を読むだけに変える（見た目は変えない）。

## 計算の流れ（1方向・時刻の順。docs/START.md の橋の約束どおり）
1 予定（ダイヤ）→ 2 予定の乗客（今の simulate）→ 3 乱れ（遅れ・事故・運休・番線）→ 4 対応（代行バス・振替・接続待ち。バス網 data/busnet.json の道と車両）→ 5 実際の乗客（乗れた・代行バス・あきらめた・遅れた）→ 6 お金（運賃・特急料金の払い戻し・代行バスの費用。決まりは data に）→ 7 まわり（売店・沿線だより・記録）。
- 同じ日の中で、うしろの段から前の段へ戻さない（乗客の変化が遅れに効くのは次の運行日から）。
- 効き目は保存しない。種・運行日・ダイヤ・条件が同じなら、どの端末でも同じ結果。
- 「試運転」の結果は記録（売店・経営・沿線だより）に残さない。
- 留守の日（js/away.js）も同じ流れの軽い版で。
- 売店・グループの収支の橋（rail-to-kiosk・rail-to-money）は、段5の「実際の乗客」を読むように向き先を変える。橋は data/links.json に1本ずつ。

## 2つのモード
| | いまの沿線 | 試運転 |
|---|---|---|
| 時刻 | 本当の今（変えられない） | 自由（×30〜×600） |
| 天気・曜日・季節 | 本当（変えられない） | 自由 |
| 選んで起こすイベント | 起こせない（暦で起きるものだけ） | 起こせる |
| 地図と指令パネル | 同じ位置 | 同じ位置（ゲームの時刻で） |
| 売店・沿線だより・記録 | 残る | 残らない |

## 進める順
1. 共通の計算（新しいファイル。ダイヤと運行日から実際の発着・番線・運休・地図の外の列車。中身は ctc-core の disrupt を呼ぶ）。運行日・ダイヤ・条件が変わったときに1回だけ計算（軽さの決まり）。
2. 指令パネルをその結果を読む形に（見た目は同じ）。**指令パネルは別の会話が作っているので、重ならない時間に**。
3. 地図を km の割合と番線で描く形に。地図の外の列車・運休の見せ方。
4. 2つのモードを分ける（画面のつまみ・記録を残す／残さない）。
5. 段4〜6（代行バス・実際の乗客・運賃と払い戻し・費用）を1本ずつ。

## 手順1でできたこと（2026-11-25）
- `js/run-record-core.js`（計算・DOM なし）：`build(inp)` が指令パネルの ensureHl と同じ順（synth → highlights → bigIncident → disrupt → setPL → yard）で計算し、列車ごとの表 `rows` を返す。
  1行＝ `{key, num, type, synth, offMap, down, seq, stop, plan:{arr,dep}, arr, dep（番線の割りふりのあとの実際）, cancel, late（終点の遅れ・分）, track:[番線], why, tr, run}`。`key` は「R/S＋種別＋番号＠始発の時刻」。
  `where(rec,row,T)` → `{st: before|stop|run|after|cancel|off, a, b, km, frac（a→b のキロの割合）, branch, track}`。`liveAt(rec,T)`・`boardAt(rec,st)` も。
  `rec.raw` に指令パネルが使う中間の結果（SYN・EXT・hl・D2・PX・SETS2・yard など）をそのまま入れた。手順2で ctc-view はこれを読めば、自分で計算しなくてよい。
- `js/run-record.js`（つなぎ）：`RunRecord.get()` を呼んだときだけ計算し、キー（運行日・ダイヤ・条件・方針・訓練）が同じなら使い回す。方針は指令パネルで選んだもの（`dia-ctc-policy`）。大きな事故の訓練は「試運転」のものなので、ふだんは起こさない（`RunRecord.set({forceBig})` で変えられる）。index.html の CtcView.init のすぐ下で init。
- まだ、どの画面もこれを読んでいない（ふだんの負荷は増えていない）。計算は1回 0.3〜0.5 秒（ヘッドレス）。手順2で指令パネルがこれを読むようにすれば、同じ計算が2回にならない。それまでは、get() を毎フレーム呼ぶものを作らないこと。
- 確かめ：`tests/run-record.test.cjs`（小さな1日）と `node tools/run-record-check.cjs plan|big|event`（本物の1日で指令パネルと比べる）。3つとも、実際の発着・番線の割りふりのあとの時刻・番線（約3,100か所）・運休・判断のカードの数が、指令パネルと完全に一致。スマホ実機は未確認。
- 残し：指令パネルの列車の位置には、信号で待つ分（LAG）が画面の中で足される。記録の `where` はそれを含まない（時刻表どおりの位置）。手順2・3で、待ちを記録の側に入れるか決める。橋（links.json）はまだ足していない（読む島ができる手順5で、rail-to-kiosk・rail-to-money の向き先を変えるときに）。

## 手順2でできたこと（2026-11-25）
- 指令パネル（js/ctc-view.js の ensureHl）は、臨時・貨物・見どころ・大きな事故・乱れ（D2）・実際の列車（PX）・編成（SETS2）を `RunRecord.get({ policy, forceBig, X, hs })` の `rec.raw` から読む。乱れを見るときの番線の割りふり（yardSets）も記録の `raw.yard` を使う。見た目は変えていない。
  RunRecord がないときは前のまま、パネルの中で計算する。「方針をくらべる」の表（ほかの方針）と、乱れを切ったとき（予定）の番線の割りふりは、今までどおりパネルの中。
  訓練の事故の日の「ふだんの日」（lateShare が読む）は、記録の訓練なしの版（同じキーならとっておいたもの）。
- RunRecord.get(opts) はキーごとに3つまでとっておく。パネルと地図（手順3）が同じキーで呼べば、計算は1回。
- 確かめ：前の版（0d33d93）と新しい版を同じ種で動かし、1日の0.5分ごとの列車の位置・信号・ポイント・判断のカード・遅れの割合・線路使用料が、予定・乱れ・事故の訓練・イベントの日の4つとも同じ（`tools/ctc-same.cjs`）。パネルの中の disrupt・synth は半分ほどに減った。スマホ実機は未確認。
- パネルの中の変数名：記録は `RREC`（`REC` は線路を描く確かめ用にすでに使われている）。

## 手順3でできたこと（2026-11-25）
- 地図（index.html の drawMap）は、`RunRecord.get()`（いまの沿線の記録＝訓練なし・方針は指令パネルで選んだもの）を `mapRec()` で読み、編成ごとに「記録の実際の時刻を持った写しの列車」（`p.rrow`・`p.base`）で setState を回す。運休の列車は写しに入れない（編成はその駅で次の列車を待つ）。
- 2駅の間：tripState が `recFrac` で記録の `where` の割合（指令パネルと同じ式。事故で止まる・交換信号所で待つもこめて）を使い、地図の線路の同じ割合の場所に置く。`where` の割合は止まる位置のずれ（列車の先頭）もこめた 0〜1 に直した。
- 待避線：途中の駅は記録の番線（`run.lanes` が外側なら待避線）で `stOff` を決める（`tr.sid`）。川辺の温泉方面の列車と、中央・港の番線は今までの決め方（地図の線は中央4本・港2本で、指令パネルより少ない）。
- 臨時（Z）・貨物（G）も地図に出す（地図の中の区間だけ。色は data/train-style.json に足した）。県央本線・港貨物ターミナルにいるあいだは、中央・港の上に札（「県央本線から 貨物 8001（00:29着）」など）。臨時が終点で休んでいるあいだは出さない。
- VIS の st は `st.run`（写し・絵と位置）と `st.trip`（もとの列車・選ぶ・札・音）。`?rr=0` で前の描き方。
- RunRecord.get()（opts なし）は、データ（ctc-extra・haisen）を読みおわるまで null（地図は前の描き方で待つ）。方針の読み出しは1秒に1回。
- 確かめ：`node tools/map-record-check.cjs 8811 1 plain|big|event`。地図の割合と記録の割合が約1.8万か所で一致・運休の12本は地図にいない・重なりは前の描き方より少し少ない・1回の描画は中央値 1.4ms で前と同じ。スマホ実機は未確認。
- 残し：列車の札・情報（trainStatus・curTrip・setWhere・乗車体験）はまだ予定の時刻。手順5か、乗車体験をつなぐときに記録へ。地図の上の札は、指令パネルの事故の訓練とは別（地図はいつも「いまの沿線」）。

## 手順4でできたこと（2026-11-25）
- 上の段の「いまの沿線」「試運転」の2つのボタン（`#liveBtn`・`#testBtn`）。保存は `dia-mode`＝`{v:1, mode, live}`（live＝試運転のあいだ覚えておく、いまの沿線の条件 MLIVE）。index.html の setMode・markMode・recCond。
- いまの沿線：本当の今（×1 いま）・本当の天気と暦・選んで起こすイベントなし・事故の訓練なし。ここで速さ・時刻（つまみ・時刻へ）・条件・イベント・シナリオ・事故の訓練を変えようとすると、止めずに試運転へ切りかえ、下に知らせ（「いまの沿線に戻る」ボタンつき）。
- 試運転：自由に変えられる。地図も指令パネルの事故の訓練を描く（RunRecord.set({forceBig})）。
- 記録を残さない：運行日の締め（ENSEN_UI.dayEnd）は試運転のあいだは何もしない。js/away.js が覚える締めの条件は recCond()（試運転のあいだは MLIVE）。試運転のまま朝4:30をまたいだら、away.js が先にいまの沿線へ戻してから締める。試運転のあいだに本当の天気が取れたら、MLIVE だけを直す。
- いまの沿線に戻ると：MLIVE の条件（イベントなし）・×1 いま・事故の訓練を切る・本当の天気を取り直す。
- はじめて（この版から）：前に選んだイベントがあるか「×1 いま」以外で遊んでいた人は、試運転から（遊んでいた条件をそのまま。締めはイベントなしの条件）。
- そのまま：指令の方針・ダイヤを組む（運行パターン）は、どちらのモードでも変えられる設定（記録に入る）。一時停止もどちらでも。乗車体験は自分の時刻で動く（今まで通り）。開発用の「次の運行日へ」は試運転のあいだ効かない。
- 確かめ：`node tools/mode-check.cjs`（9項目。試運転で雪・日曜・花火にしたまま日をまたいでも、締めはいまの沿線の条件・イベントなし）。スマホの幅の見た目もヘッドレスで確認。スマホ実機は未確認。
- 気づいて直したこと：開発用の minatoAway.test(n) が締めの条件に今の COND を書いていた（recCond に）。
