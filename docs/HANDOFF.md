## 守ること
- 今の機能を壊さない。大きな書き換えはしない。計算（*-core.js）と画面（*-view.js）を分ける。設定は data/。名前はすべて架空。proto/ に触らない。push の前に fetch と rebase。返事はやさしい日本語。確かめたのがヘッドレスだけなら、スマホ実機は未確認と書く。
- **めざす方向（[VISION.md](VISION.md)）**：現実の社会を出発点に、少し先の未来が見えるシミュレーション。結果は先に決めない。中心の島は作らない。島は独立して動き、必要な数字だけを交換する。数字の出どころを「現（real）・仮（assume）・内（game）」で分ける。1回に橋1本。
- **因果と時刻の順を省かない**：列車の到着 → 駅の人の流れ → 売店の販売 → 在庫 → 発注 → 配送 → 稼働と収支。描画や不要な計算は減らしてよいが、出来事はゲーム内の時刻の順に処理し、画面を開いていなくても・高速でも結果を変えない。日次の集計は記録と分析用で、日中の因果を失わせない。**描画を止めることと、ゲームの時間・経済活動を止めることは別**（切りかえ・スリープ・復帰で欠落や二重計算を出さない）。
- **軽さ**：つないでも、Claude の使用量とスマホの CPU・電池を大きく増やさない（機能を削るのではなく、計算方法と設計で）。駅ごとのちがいと、事業の広がりは保つ。測るのは `index.html?perf=1` と `tools/perfcmp.py`。
- **長く育てるための4つの決まり（2026-11-06 夜に決めた。11/9 から守る）**
  1. **橋の約束の形**：`data/links.json` の1本ごとに `id`（一度決めたら変えない）・`from`・`to`・`values:[{name,unit,src}]`・`state`（done 実装済み／temp 仮の数値／none 未接続／retired 廃止）・`strength`・`read`（いつ読むか：`when` と確定した時刻 `at`）・`desc`。やめる橋は消さずに `retired`。
  2. **読むのは自分より前に確定した数字だけ（一方向・時刻の順）**。同じ時刻・同じ日の中で2つの島が読み合う輪は作らない。両方向に効くときは、片方を「前の日（もっと前の時刻）の確定した結果」にする。橋で渡す数字は `{day, t, value}` の形にできるようにしておく（t＝確定したゲーム内の分。当日の連携、例「8:00 出荷 → 10:00 到着 → 12:00 販売」のため）。
  3. **つなぎの効き目は保存しない**：倍率・補正は、決まった乱数とその日の条件から毎回計算し直す（dia- のキーにも引き継ぎコードにも入れない）。
  4. **新しく作る保存には版の番号 `v` を最初から付ける**（`{v:1,...}`）。既存のキーの形は変えない。古い保存を直すプログラムは、形を変えるときに作る。
